## Static vs. dynamic object design
**Dynamic models**: Design the logic and behavior of code or method bodies.
- Examples: UML interaction diagrams, sequence diagrams, and communication diagrams.
- These tend to be the more interesting, challenging, and important diagrams.

**Static models**: Design packages, classes, attributes, and method signatures, excluding method bodies.
- Examples: UML class diagrams, package diagrams, and object diagrams.

*Agile modeling practice*:
- Spend a short time on interaction diagrams (dynamic), then create the related class diagrams (static).

## The importance of object design skills
Drawing *UML* is a way to help make design decisions, rather than merely documenting decisions that have already been made.
What matters is object design skill, not how to draw UML.
**Fundamental knowledge for object design**:
- Responsibility assignment principles.
- Design patterns.
