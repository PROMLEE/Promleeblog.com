This part takes a closer look at *caching and revalidation* and the advanced options of `fetch`.

## Fetch caching in Next.js
Next.js caches all `fetch` requests by default.
In other words, it reuses the same response when an identical request occurs multiple times, reducing server resource use and improving response speed.
However, cached data is not always desirable.
For frequently changing data, you need a way to disable caching or refresh it at intervals.

## Disabling caching with cache: 'no-store'
By default, Next.js tries to fetch data at build time and serve it statically.
For real-time data, disable caching as follows.
```tsx
const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
  cache: 'no-store',
});
```
This fetches fresh data for every request.

## Incremental static regeneration through revalidation
Use the `next.revalidate` option to *revalidate statically cached data after a specified interval*.
This approach is called ISR, or Incremental Static Regeneration.
Example:
```tsx
const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
  next: { revalidate: 60 }, // 60초마다 새로 데이터를 가져옵니다
});
```
With this configuration, the first page request uses the static cache, and after 60 seconds the data is fetched again in the background.
This balances performance and freshness.

## How cache keys are generated
Next.js internally creates a *unique cache key* based on the request URL, headers, cookies, and related information.
Different URLs or request headers therefore result in separate cache entries.
For example, these two requests have different cache keys.
```ts
// 서로 다른 캐시 키
fetch('https://api.example.com/data?lang=en')
fetch('https://api.example.com/data?lang=ko')
```
When *responses need to differ per request*, such as by locale, user permissions, or theme, explicitly distinguish them through query parameters or headers.

## Caching strategy summary
| Strategy | Configuration | Description |
|------|-----------|------|
| Static cache (default) | None | Fetches at build time and uses cached data |
| No caching | cache: 'no-store' | Always retrieves fresh data |
| ISR | next: \{ revalidate: n \} | Refreshes the cache in the background every n seconds |

## Example: Revalidating posts periodically
```tsx
export default async function Page() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    next: { revalidate: 3600 }, // 1시간마다 재검증
  });
  const posts = await res.json();
  return (
    <ul>
      {posts.map((post: { id: number; title: string }) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```
This code serves cached data for page requests, automatically fetching it again after one hour.
