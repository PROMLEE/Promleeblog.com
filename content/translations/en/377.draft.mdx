## 1. Smooth screen changes with View Transitions

Web apps can feel abrupt or flash when pages change.
React 19 and Next.js 16 support the browser's *View Transitions API*, enabling smooth transitions without a heavy animation library.

### How do you use it?
React 19's `startTransition` now supports asynchronous functions, allowing the previous screen to remain visible while data loads before transitioning smoothly to the new screen.

```tsx title="app/components/TabSwitcher.tsx" showLineNumbers {7,11-17}
'use client';

import { useTransition, useState } from 'react';
import { fetchTabData } from './actions';

export default function TabSwitcher() {
  const [isPending, startTransition] = useTransition();
  const [data, setData] = useState(null);

  function handleTabClick(tabId: string) {
    // [핵심] startTransition으로 상태 업데이트를 감쌉니다.
    // React는 이 작업이 완료될 때까지 UI를 차단하지 않고,
    // 브라우저의 View Transition API와 연동하여 부드러운 전환을 준비합니다.
    startTransition(async () => {
      const newData = await fetchTabData(tabId);
      setData(newData);
    });
  }

  return (
    <div>
      <div className="tabs">
        <button onClick={() => handleTabClick('home')}>Home</button>
        <button onClick={() => handleTabClick('settings')}>Settings</button>
      </div>
      
      {/* 데이터 로딩 중에는 투명도를 조절하는 등 시각적 피드백 제공 가능 */}
      <div style={{ opacity: isPending ? 0.5 : 1 }}>
        {data ? <Content data={data} /> : <p>Select a tab</p>}
      </div>
    </div>
  );
}
```

## 2. Stronger Server Actions security

Next.js 16 strengthens security when using *Server Actions*.
When importing server functions into client components, more aggressive *dead code elimination* helps prevent server-only code from entering the client bundle accidentally.

### Why does this matter?
It helps prevent accidentally sending database secrets or internal server logic to the client.
The Next.js 16 compiler optimizes calls so the client refers to **only the action's ID**.

```ts title="app/actions.ts" showLineNumbers {1,6}
'use server';

// 이 함수 내부의 로직(DB 접근 등)은 절대 클라이언트로 유출되지 않습니다.
export async function submitForm(formData: FormData) {
  const apiKey = process.env.API_KEY; // 서버 환경 변수
  await saveToDb(formData, apiKey);
  return { success: true };
}
```

## 3. A new hook for UX: useOptimistic

When you send a chat message, its bubble often appears before the server responds.
Implementing this kind of *optimistic update* used to be fairly complicated.
React 19's `useOptimistic` makes it much simpler.

```tsx title="app/components/MessageList.tsx" showLineNumbers {7-13,19}
'use client';

import { useOptimistic, useRef } from 'react';
import { sendMessage } from './actions';

export default function MessageList({ messages }: { messages: string[] }) {
  // [핵심] useOptimistic 훅 사용
  // optimsticMessages: 화면에 보여줄 임시 상태
  // addOptimisticMessage: 임시 상태를 추가하는 함수
  const [optimisticMessages, addOptimisticMessage] = useOptimistic(
    messages,
    (state, newMessage: string) => [...state, newMessage]
  );

  async function action(formData: FormData) {
    const message = formData.get('message') as string;
    
    // 1. 서버 요청을 보내기 전에 화면에 먼저 표시 (낙관적 업데이트)
    addOptimisticMessage(message);
    
    // 2. 실제 서버 요청 (실패 시 React가 알아서 상태를 롤백해 줍니다)
    await sendMessage(message);
  }

  return (
    <div>
      {optimisticMessages.map((m, i) => <div key={i}>{m}</div>)}
      <form action={action}>
        <input name="message" />
        <button type="submit">Send</button>
      </form>
    </div>
  );
}
```

## 4. useEffectEvent and Activity

Two more React Canary features included in Next.js 16 deserve attention.

### useEffectEvent
Sometimes values inside `useEffect` should be *reactive*, while others should not.
For example, you may want to log a connection only when the chat room changes, while still reading the latest theme color.
`useEffectEvent` lets you read current values without rerunning the effect.

### Activity (Offscreen)
Have you ever switched tabs and returned to find your scroll position or input lost?
The `<Activity>` component preserves state by hiding an offscreen component, similarly to CSS `display: none`, instead of *unmounting* it.
Returning to the screen can therefore reveal its previous state immediately.
