## Before We Begin
Hello!
Having explored the powerful features of Next.js 16 in the previous posts, it is time to put them into practice.
I will walk you through safely upgrading your project to Next.js 16, step by step.<br/>
This involves more than updating package versions: several *breaking changes* require code changes, so follow along carefully.

## 1. Use the Automated Upgrade Tool (Codemod)

The Next.js team provides a powerful automation tool to help with upgrades.
I strongly recommend using it instead of updating versions manually.
<br/>
Open a terminal in your project folder and run the following command.

```bash title="Terminal" showLineNumbers
npx @next/codemod@canary upgrade latest
```

This command performs the following tasks:
- Updates the Next.js, React, and React DOM versions in `package.json` to the latest versions.
- Updates the `next.config.js` configuration file, including removing unsupported options.
- Automatically applies some API changes.
<br/>
However, the command cannot fully understand and fix your business logic.
The following are *required changes* that developers need to handle themselves.

## 2. Required Changes: Adopt Asynchronous APIs

The first and most common errors you will encounter concern synchronous API access.
As explained in part 2, runtime data access in Server Components must now be **asynchronous**.

### Update params and searchParams
You need to change the page component's `props` type and how you use it.

```tsx title="app/blog/[slug]/page.tsx" showLineNumbers {5-6}
// [변경 전]
// export default function Page({ params }: { params: { slug: string } }) { ... }

// [변경 후]
// 1. Props 타입: params를 Promise로 감싸줍니다.
export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  
  // 2. 데이터 접근: 반드시 await를 사용하여 값을 추출해야 합니다.
  // await 없이 params.slug에 접근하면 런타임 에러가 발생합니다.
  const { slug } = await params;

  return <div>Blog Post: {slug}</div>;
}
```

### Update cookies and headers
The functions imported from `next/headers` also require `await`.

```tsx title="app/layout.tsx" showLineNumbers {6}
import { cookies } from 'next/headers';

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  // [변경] cookies() 호출 앞에 await를 붙여야 합니다.
  // 이전 버전(v15)에서는 경고만 떴지만, v16에서는 에러가 발생합니다.
  const cookieStore = await cookies();
  const theme = cookieStore.get('theme');
  
  return (
    <html lang="en" className={theme?.value}>
      <body>{children}</body>
    </html>
  );
}
```

## 3. Stricter next/image Security Settings

The image optimization component's default settings have changed.
They are now a little stricter for security and performance.

### Allow Query Strings for Local Images
If you have been using query parameters such as `?v=1` in local image paths, you must now explicitly allow them in `next.config.js`.
This prevents unrestricted image generation.

### Allow Local IP Addresses on Private Networks
If you need to load images from local IP addresses on a private network, rather than a development environment (`localhost`), enable the `dangerouslyAllowLocalIP` option.

```js title="next.config.js" showLineNumbers {6-9,12}
module.exports = {
  images: {
    // 1. 로컬 이미지에 쿼리 스트링 사용 시 패턴 명시 필요
    localPatterns: [
      {
        pathname: '/assets/**',
        search: '?v=1',
      },
    ],

    // 2. 사설망 등에서 로컬 IP로 이미지 로드 시 필요 (보안 주의)
    // 기본값은 false로 변경되었습니다.
    dangerouslyAllowLocalIP: true, 
  },
};
```

## 4. Parallel Routes: default.js Is Required

Take care if you use *Parallel Routes*, with the `@folder` format.
Now, if a slot does not have a corresponding `default.js` file, **the build itself fails**.
<br/>
Previously, Next.js would handle this with a 404 or ignore it. Now developers must explicitly declare that there is nothing to display.

```tsx title="app/@analytics/default.tsx" showLineNumbers {3-4}
// 해당 슬롯에 보여줄 기본 컨텐츠가 없더라도 파일은 생성해야 합니다.
export default function Default() {
  // 아무것도 렌더링하지 않으려면 null을 반환합니다.
  return null;
}
```

## 5. Rename the Middleware File

Rename the `middleware.ts` (or .js) file in your project root to **proxy.ts**.
You must also rename its exported function from `middleware` to `proxy`.

```bash title="Terminal"
# 파일명 변경
mv middleware.ts proxy.ts
```

```ts title="proxy.ts" showLineNumbers {4-5}
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

// [변경] 함수 이름을 proxy로 수정
export function proxy(request: NextRequest) {
  return NextResponse.next();
}
```

## 6. Remove Unsupported Features

Finally, remove features that are no longer supported from your code.

- **Remove AMP configuration**
Remove any use of `config.amp` or the `useAmp` hook.
- **Remove the next lint command**
Linting no longer runs automatically during `next build`.
Add a separate `eslint` command to your CI/CD pipeline.
- **Replace Legacy Image**
The `next/legacy/image` component has been removed.
Replace it with the standard `next/image`.

## Conclusion

Migrating to Next.js 16 means more than updating a version number.
It is a chance to improve your application's foundations and long-term maintainability through *asynchronous APIs* and *explicit caching*.
<br/>
By carefully following this post and the reference links below, you should be able to complete your migration without major problems.
Thank you.
