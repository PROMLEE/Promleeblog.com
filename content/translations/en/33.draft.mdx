## Digital signature overview
### Message authentication
When Bob sends Alice a message, Alice needs to verify that it came from Bob $\rightarrow$ use a *digital signature*.
1. Bob generates a signature using his private key.
2. Alice verifies it using Bob's public key.

No one can generate Bob's signature without his private key.
This authenticates the source, Bob, and the integrity of the message data.

### Digital signatures
A digital signature scheme consists of three polynomial-time algorithms.
- *KeyGen*($\lambda$) $\rightarrow$ (pk, sk): Key generation.
	- Takes a security parameter $\lambda$ and generates a public key (pk) and private key (sk).
- *Sign*(sk, m) $\rightarrow$ $\sigma$: Signing.
	- Takes a private key (sk) and message (m) and produces a digital signature ($\sigma$).
- *Verify*(pk, m, $\sigma$) $\rightarrow$ \{0, 1\}: Verification.
	- Takes a public key (pk), message (m), and digital signature ($\sigma$) and checks whether the signature is valid.
	- Returns 1 if valid, and 0 otherwise.

### Verification
**Correctness**: The verification algorithm must satisfy the following.
- For every security parameter $\lambda$ and message $m$:
- $\text{Verify}(pk, \text{Sign}(sk, M)) = 1$ must hold.
- Here, $(pk, sk) \leftarrow \text{KeyGen}(\lambda)$.

#### Digital signature summary
- Digital signatures provide message authentication and data integrity.
- A digital signature scheme consists of the polynomial-time algorithms *KeyGen*, *Sign*, and *Verify*.
- It must satisfy correctness: $\text{Verify}(pk, \text{Sign}(sk, M)) = 1$.

## The digital signature security model
Consider a game between a challenger $C$ and attacker $A$.
1. Setup: $C$ runs KeyGen($\lambda$) to generate $(pk, sk)$, then gives the public key $pk$ to $A$.
2. Signing queries: $A$ requests signatures for messages $M_i$ a polynomial number of times.
	- For each $M_i$, $C$ executes $\text{Sign}(sk, M_i) → \sigma_i$ to generate a signature $\sigma_i$ and returns it to $A$.
3. Output: $A$ returns $(M, \sigma)$.
	- $M$ is a message that $C$ has not signed and differs from the messages for which $A$ requested signatures.
	- If $A$ produces a valid signature for $M$, namely $\sigma$, then $A$ succeeds.

The success probability of $A$ is defined as follows.
- $$\Pr[\text{Verify}(pk, \text{Sign}(M, \sigma)) = 1]$$

The signature scheme is strongly unforgeable under an adaptive chosen-message attack.
If the probability that a polynomial-time attacker $A$ succeeds in this game is negligible, the scheme is strongly *unforgeable*.
