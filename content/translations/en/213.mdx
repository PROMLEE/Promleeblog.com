## Classic Synchronization Problems
### Producer-Consumer Problem
A producer adds data to a shared buffer, while a consumer removes it. Each must wait appropriately when the buffer is full or empty.
Solution: use two semaphores and a mutex to coordinate the producer and consumer.
```c title="C 코드"
sem_t empty, full;
pthread_mutex_t mutex;

void producer() {
  while (1) {
    // 데이터 생성
    sem_wait(&empty); // 버퍼가 비어있는지 확인
    pthread_mutex_lock(&mutex); // 버퍼에 접근하기 위한 락
    // 데이터 추가
    pthread_mutex_unlock(&mutex); // 락 해제
    sem_post(&full); // 버퍼가 채워진 것을 알림
  }
}

void consumer() {
  while (1) {
    sem_wait(&full); // 버퍼가 채워진 것을 확인
    pthread_mutex_lock(&mutex); // 버퍼에 접근하기 위한 락
    // 데이터 소비
    pthread_mutex_unlock(&mutex); // 락 해제
    sem_post(&empty); // 버퍼가 비어있는 것을 알림
  }
}
```
### Dining Philosophers Problem
Five philosophers sit around a circular table, with one fork between each pair. Each philosopher must acquire both the left and right forks before eating. This creates a synchronization problem.
Problem: if all philosophers pick up one fork at the same time and wait, a deadlock can occur.
Solution: use strategies such as varying the fork acquisition order for odd- and even-numbered philosophers, or limiting the number of participating philosophers.

## Synchronization Inside the Kernel
Synchronization is essential inside the operating system too, because multiple processes can access the kernel concurrently through system calls.
For example, when multiple processes try to modify the same file, a file system uses a *lock* to coordinate their order.
Solutions include spinlocks and reader-writer locks.
### Spinlocks
A spinlock repeatedly spins while waiting for a lock to be released.
A thread that cannot acquire it keeps looping (*attempting the lock*) rather than yielding the CPU.
- No context switch → useful when a lock is held for a very short time.
- Common in multicore environments.
- Inefficient when locks are held for a long time, wasting CPU cycles.
- Generally used in kernels or code close to the hardware.
```c title="C 코드"
while (__sync_lock_test_and_set(&lock, 1)) {
  // 락이 해제될 때까지 계속 대기 (spin)
}
```
### Reader-Writer Locks
A reader-writer lock controls reads and writes separately.
Multiple readers can access data simultaneously, allowing parallel reads.
A writer has exclusive access, blocking both reads and writes.
- Improves performance when reads are frequent and writes are rare.
- Maximizes concurrency while preserving data consistency.
- Read lock: multiple threads can acquire it simultaneously.
- Write lock: only one thread can acquire it exclusively.
- Reader-priority or writer-priority policies can be chosen.
```c title="C 코드"
pthread_rwlock_t lock;
pthread_rwlock_rdlock(&lock);  // 읽기 락
// 읽기 작업 수행
pthread_rwlock_unlock(&lock);  // 락 해제

pthread_rwlock_wrlock(&lock);  // 쓰기 락
// 쓰기 작업 수행
pthread_rwlock_unlock(&lock);  // 락 해제
```

## POSIX Thread Synchronization Examples
> What is POSIX?
POSIX stands for Portable Operating System Interface, a project providing standardized operating system interfaces. POSIX standards are designed to ensure consistent behavior across operating systems. Most operating systems we use, such as Linux, macOS, and Windows, follow POSIX standards.

In a POSIX environment, the `pthread` library provides access to mutexes and semaphores.
```c
pthread_mutex_t lock;
pthread_mutex_init(&lock, NULL);
pthread_mutex_lock(&lock);
// 임계구역 코드
pthread_mutex_unlock(&lock);
```
Semaphore example:
```c
sem_t sem;
sem_init(&sem, 0, 3); // 동시 접근 가능 횟수: 3
sem_wait(&sem);
// 공유 자원 접근
sem_post(&sem);
```
## Synchronization in Java
Java's `synchronized` keyword makes it easy to define a critical section.
```java
public synchronized void increment() {
  count++;
}
```
Alternatively, use an explicit lock object:
```java
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
  // 임계구역
} finally {
  lock.unlock();
}
```

## Alternative Approaches
Although synchronization problems are difficult to avoid entirely, structural alternatives can reduce the risks.
- Asynchronous processing: distribute resource access to minimize the need for locks.
- Lock splitting: lock only part of a resource rather than the whole thing.
- Lock-free structures: use CAS-based data structures.

These techniques are increasingly common in high-performance systems.
