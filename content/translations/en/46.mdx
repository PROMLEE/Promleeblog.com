## Introduction
1. Source symbols must be encoded in *binary*.
2. Average code length should be minimized.
3. Remove redundancy $\rightarrow$ reduce the bit rate.
<br/>

- Consider a discrete memoryless source over the alphabet $S = \{s_0, s_1, \ldots, s_k\}$.
- The probability of $s_i$: $p_{i}$.
- The code length for $s_i$: $l_i$.
- Average code length, or average bits per symbol: $L = \sum_{k=0}^{K-1} p_k \cdot l_k$.
<br/>

- The minimum possible value of $L$: $L_{min}$.
- Coding efficiency of the source: $\eta=\frac{L_{min}}{L}$.
<br/>

- Data compression:
	1. Remove redundant information before transmission.
	2. Use lossless data compression.
	3. A source code representing the output of a discrete memoryless source must be uniquely decodable.

## Source coding schemes for data compression
### Prefix coding
> A variable-length source code in which *no codeword is a prefix of another*.
- Properties of prefix codes:
	1. Every prefix code is uniquely decodable.
	2. The converse is not always true: Not every uniquely decodable code is a prefix code.

#### Prefix-code example
| Symbol | Probability | Code I | Code II | Code III |
| --- | --- | --- | --- | --- |
| s0 | 0.5 | 0 | 0 | 0 |
| s1 | 0.25 | 1 | 10 | 01 |
| s2 | 0.125 | 00 | 110 | 011 |
| s3 | 0.125 | 11 | 111 | 0111 |

Code 1: Not a prefix code.
Code 2: A prefix code.
Code 3: Uniquely decodable, but not a prefix code; identifying the next codeword's start is difficult.
For example, Code 2:
0101110111 → 0/10/111/0/111 → uniquely decodable.

An arbitrary symbol $s_k$ occurs with probability $p_k=2^{-l_k}$.
- Sum of probabilities: $1 = \sum_{k=0}^{K-1} p_k = \sum_{k=0}^{K-1} 2^{-l_k}$.
- Average code length: $L = \sum_{k=0}^{K-1} p_k \cdot l_k = \sum_{k=0}^{K-1} 2^{-l_k} \cdot l_k$.

## * Huffman coding
⭐ **Important** ⭐
### The Huffman coding algorithm
A commonly used compression method that *compresses data* by assigning short codewords to frequent symbols and longer codewords to rare symbols.

1. Arrange symbols in descending probability order and treat them as leaf nodes.
2. Repeat the following until one node remains.
	- Select the two least probable nodes. Assign 0 to the less probable one and 1 to the other; the opposite assignment also works, provided it is consistent.
	- Merge the two into a node whose probability is the sum of their probabilities.
	- Return to step 1.
3. For each symbol, generate its binary code by following the path from its leaf node to the root.
	- The bit at the leaf becomes the final bit of the codeword.

### Properties of Huffman codes
They are prefix codes.
The codeword length for each symbol approximately matches the information it conveys.
Huffman coding is highly effective when the probability distribution is known and accurate.
- Variance measures variation in codeword length.
$\sigma^2 = \sum_{k=0}^{K-1} p_k (l_k - \overline{L})^2$
- Choose a Huffman tree with *higher variance* to help avoid errors.
	→ A higher-variance tree has more diverse codeword lengths and can handle errors better.
