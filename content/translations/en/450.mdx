## Before We Begin

I built a service that summarizes uploaded documents and answers questions about them. The first customer paid 20,000 won for a month. How much of the deposit can I spend? I still have API bills and development subscriptions for tools such as Codex or Claude.
<br/>
We'll calculate **whether another customer brings the service closer to breaking even**. The service and usage figures are hypothetical, and the monthly price of 20,000 won is illustrative. These are not actual sales or usage logs. Pricing was checked on October 15, 2026. For the calculations, assume 1,400 won per U.S. dollar.

## Payment and Revenue

Assume a domestic Korean sale by a general VAT taxpayer at a 10% VAT rate. For the rate and basic rules on input tax credits, see the [National Tax Service VAT overview](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7693&mi=2272). Treating the entire payment as revenue would include money set aside for tax in the profitability calculation.

| Item | Calculation | Monthly amount per user |
| --- | --- | --- |
| Customer payment | Example price | 20,000 won |
| Revenue excluding VAT | 20,000 ÷ 1.1 | About 18,182 won |
| Payment processing fee | Assumed 3.3% of payment | 660 won |
| Refunds and discounts | Base scenario | 0 won |

The 3.3% is an assumption, not a payment processor's contract rate. **Revenue here excludes VAT, and the processing fee is deducted once as a variable cost.** Avoid deducting it again from a payout that already excludes the fee. For refunds and discounts, adjust the period's revenue and check whether processing fees were returned.

## Development Tools and Infrastructure

Development subscriptions and the API that generates customer answers serve different purposes. ChatGPT Plus with Codex and Claude Pro with Claude Code are each USD 20 on monthly billing in this example. Annual Claude Pro billing is USD 200 paid upfront, which changes when cash leaves the business. [OpenAI pricing](https://learn.chatgpt.com/docs/pricing), [Claude pricing](https://claude.com/pricing)
<br/>
Include the server and database too. Supabase Pro starts at USD 25 a month, and this example assumes one Micro instance covered by the included compute credits. For Vercel Pro, assume USD 20 a month for one developer and no usage beyond the included allowance. [Supabase pricing](https://supabase.com/pricing), [Vercel pricing](https://vercel.com/pricing)

| Monthly cost | Assumption based on official pricing | In Korean won |
| --- | --- | --- |
| Supabase Pro | USD 25 | 35,000 won |
| Vercel Pro | USD 20 | 28,000 won |
| One development subscription, Codex or Claude | USD 20 | 28,000 won |
| Base total | USD 65 | 91,000 won |
| With both development subscriptions | USD 85 | 119,000 won |

This is *a model of a basic setup*. Actual bills can differ. The model excludes extra seats, compute, traffic, domains, email, and card currency conversion fees. It excludes deductible input VAT. Add nondeductible tax based on your actual records.
<br/>
Subscriptions paid even when customers make no requests are fixed costs here. Development API calls and overages can vary with usage, so classify them accordingly. If you develop several services, record the total subscription spend and the amount allocated to each service. Avoid charging the entire bill to every service.

<Bbox>
If one tool is enough, a second subscription is optional. The base case assigns one subscription's full cost to this service and treats two subscriptions as a separate scenario.
</Bbox>

## Contribution Margin per User

Contribution margin is revenue after variable costs. The combined margin from paying users covers fixed costs. Assume 200 successful tasks per user per month at 43.64 won per successful task. The next article shows how to reproduce that cost with official API rates, sample request logs, and retries.

```text
사용자당 작업 원가 = 200 × 43.64 = 8,728원
사용자당 공헌이익 = 20,000 ÷ 1.1 − 660 − 8,728
                  ≈ 8,794원
월 운영 잔액 = 유료 사용자 수 × 공헌이익 − 91,000원
손익분기 사용자 수 = 올림(91,000 ÷ 공헌이익) = 11명
```

At 200 tasks, the task cost is 8,728 won per user. Subtract that and the 660-won processing fee from VAT-exclusive revenue to get a contribution margin of about 8,794 won. Multiply the margin by the number of paying users, then subtract 91,000 won to get the monthly operating balance.

**With baseline usage, 11 paying users cover the costs included here.** At 10 users there is a shortfall of about 3,062 won. At 11 users there is about 5,732 won left. Calculations use unrounded values and round only the displayed won amounts.

With two subscriptions, fixed costs rise to 119,000 won and break-even moves to 14 users. Judge whether the second tool saves more than 28,000 won a month in development and maintenance time. Time saved only becomes revenue if you turn it into sales.

## How Usage Changes the Result

Average usage matters as much as pricing. A customer paying the same 20,000 won can cost much more to serve if they run ten times as many tasks.

| User type | Successful tasks per month | Task cost | Contribution margin per user |
| --- | --- | --- | --- |
| Light | 50 | 2,182 won | About 15,340 won |
| Baseline | 200 | 8,728 won | About 8,794 won |
| Heavy | 500 | 21,820 won | About −4,298 won |

*Adding customers can make the loss larger.* If every new customer runs 500 tasks, each adds to the deficit, so there is no valid break-even user count under these assumptions. With 90 baseline users and 10 heavy users, the monthly operating balance is about 657,462 won. With 100 baseline users, it is about 788,382 won.
<br/>
Retry rates and document length also affect costs. Caching and model choice can lower API costs. Check that the share of answers passing your quality checks holds up. ## What the Calculation Covers

This worksheet is a first operating check. It excludes developer labor, support time, and customer acquisition. For example, valuing 20 hours of development and support at 30,000 won an hour adds 600,000 won a month. With the base fixed costs, recovering 691,000 won takes 79 users at the same usage level.
<br/>
Some costs jump at certain scales, such as adding server capacity or hiring support. A straight line with fixed overhead cannot describe those ranges. Recalculate when usage, quality, or infrastructure costs change.

## Conclusion

After the first payment, ask **how much is left when one more person uses the service**. Enter your price, monthly base costs, allocated development expenses, and tasks per user. Compare average usage with a scenario in which more customers use the service heavily.
