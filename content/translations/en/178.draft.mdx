## Data fetching overview
Next.js App Router operates on React Server Components (SSR).
Server components can use server-only capabilities unavailable in the browser, including data fetching.
Next.js generally recommends *fetching data on the server*.
Doing so prepares the HTML before sending it to the client, which benefits loading speed and SEO.
### When and where should you fetch data?
Next.js can retrieve data in these places:
- *Server components (the default)*: Recommended for most data.
- *Client components*: Used when data must be retrieved dynamically after user interaction.
- *Route handlers (API routes)*: Act as backend APIs and communicate with external systems.
Because App Router uses folder-based routing, data is fetched inside component files in the `app/` directory.

## The basics of fetch
The function most commonly used to retrieve data in Next.js is `fetch`.
It is almost the same as the browser's native `fetch`, but Next.js gives it special behavior.
For example, the following code retrieves posts from JSONPlaceholder.
```tsx title="app/page.tsx"
export default async function Page() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const posts = await res.json();
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```
The code runs in a server component and fetches data before rendering HTML.
Compared with fetching data on the client and showing a loading state, this can provide a faster and more stable user experience.

## How fetch works and its features
Next.js `fetch` has the following features.
- Automatic caching: By default, `fetch` caches identical requests.
- Cache control: Disable caching through configuration with `cache: 'no-store'`.
- ISR support: Configure periodic updates with `next.revalidate`.
