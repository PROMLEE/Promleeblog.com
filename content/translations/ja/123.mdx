## はじめに
> この記事はFlutter 3.24を前提にしています。

アプリやWebのフロントエンドを開発すると、バックエンドや公開APIを使うことがあります。APIを呼び出すにはHTTP通信が必要です。Flutterでは、DioとRetrofitを使って通信できます。
HTTPパッケージでも通信できますが、DioとRetrofitを組み合わせると、APIをより手軽に呼び出せます。特にRetrofitでは、型を定義することでレスポンスを扱いやすくなり、開発効率が上がります。
この記事では、FlutterでDioとRetrofitを使って通信する手順と、型を定義する重要性を見ていきます。

## 1. パッケージをインストールする
Retrofitを使うために、DioやRetrofitなどのパッケージをインストールします。開発時だけ使う3つのパッケージはdev_dependenciesに追加します。
次のコマンドでインストールします。
```
dart pub add json_annotation dio retrofit
dart pub add --dev build_runner retrofit_generator json_serializable
```
pubspec.yamlに次のように追加されているか確認します。バージョンは記事執筆時点のものです。
```yaml title="pubspec.yaml"
dependencies:
	retrofit: ^4.4.2
	dio: ^5.7.0
	json_annotation: ^4.9.0

dev_dependencies:
	build_runner: ^2.4.13
	retrofit_generator: ^9.1.5
	json_serializable: ^6.9.0
```
各パッケージの役割は次のとおりです。
- dioは、HTTP通信に使います。
- retrofitは、APIとの通信に使います。
- json_annotationは、JSONのシリアライズとデシリアライズに使います。
- build_runnerは、コード生成に使います。
- retrofit_generatorは、Retrofitで使うコードを生成します。
- json_serializableは、APIのやり取りでJSONをシリアライズ、デシリアライズするコードを生成します。

### 2.1. APIリクエスト用のモデルクラスを書く
APIリクエストに使うモデルクラスを作ります。次はコード例です。
```dart title="lib/model/user_dto.dart"
import 'package:json_annotation/json_annotation.dart';
part 'user_dto.g.dart';

@JsonSerializable()
class UserDto {
	final int id;
	final String name;
	final String username;
	final String email;
	final Address address;
	final String phone;
	final String website;
	final Company company;

	UserDto({
		required this.id,
		required this.name,
		required this.username,
		required this.email,
		required this.address,
		required this.phone,
		required this.website,
		required this.company,
	});

	factory UserDto.fromJson(Map<String, dynamic> json) => _$UserDtoFromJson(json);
	Map<String, dynamic> toJson() => _$UserDtoToJson(this);
} 

@JsonSerializable()
class Address {
	final String street;
	final String suite;
	final String city;
	final String zipcode;
	final Geo geo;

	Address({
		required this.street,
		required this.suite,
		required this.city,
		required this.zipcode,
		required this.geo,
	});

	factory Address.fromJson(Map<String, dynamic> json) => _$AddressFromJson(json);
	Map<String, dynamic> toJson() => _$AddressToJson(this);
}

@JsonSerializable()
class Geo {
	final String lat;
	final String lng;

	Geo({
		required this.lat,
		required this.lng,
	});

	factory Geo.fromJson(Map<String, dynamic> json) => _$GeoFromJson(json);
	Map<String, dynamic> toJson() => _$GeoToJson(this);
}

@JsonSerializable()
class Company {
	final String name;
	final String catchPhrase;
	final String bs;

	Company({
		required this.name,
		required this.catchPhrase,
		required this.bs,
	});

	factory Company.fromJson(Map<String, dynamic> json) => _$CompanyFromJson(json);
	Map<String, dynamic> toJson() => _$CompanyToJson(this);
}
```

### 2.2. APIリクエスト用のインターフェースを書く
```dart title="lib/model/user.dart"
import 'package:dio/dio.dart';
import 'package:retrofit/retrofit.dart';
import 'user_dto.dart';

part 'user.g.dart'; // 생성될 파일

@RestApi(baseUrl: "https://jsonplaceholder.typicode.com") // base url
abstract class UserApi {
	factory UserApi(Dio dio, {String baseUrl}) = _UserApi;

	@GET("/users") // 요청할 API
	Future<List<UserDto>> getUsers(); // 요청할 API의 응답을 받을 모델 클래스
}
```
## 3. コードを生成する
上のコードを書いた時点では、IDEにエラーを示す赤い線が出ることがあります。コードの生成が必要という意味です。
プロジェクトのルートで、次のコマンドを実行します。
```
dart run build_runner build
```
対象のフォルダーに次のファイルが生成されているか確認します。
```
lib/model/user_dto.g.dart
lib/model/user.g.dart
```
エラーが消えたら、APIを呼び出せる状態です。

## 5. 追加設定
### 5.1. リクエストにパラメーターを渡す
```dart
@GET('/users/{id}')
Future<UserDto> getUserByPathId(@Path() int id); // 파라미터 전달
```
### 5.2. リクエストにクエリパラメーターを渡す
```dart
@GET('/users')
Future<List<UserDto>> getUserByQueryId(
	@Query('id') int id,
); // 쿼리 파라미터 전달
```
### 5.3. リクエストにヘッダーを渡す
固定のヘッダーは次のように書きます。
```dart
@GET('/users')
@Headers(<String, dynamic>{
	'Content-Type': 'application/json',
	'Authorization': 'Bearer {token}',
})
Future<List<UserDto>> getUsers(); // 헤더 전달
```
動的にヘッダーを渡す場合は次のように書きます。
```dart
@GET('/users')
Future<List<UserDto>> getUsers(
	@Header('Content-Type') String content_type, 
	@Header('Authorization') String authorization,
); // 헤더 전달
```
### 5.4. リクエストにボディを渡す
```dart
@POST('/users')
Future<UserDto> createUser(@Body() UserDto user); // 바디 전달
```

## 問題と対処法
### 1. クラス名を変えた場合
リクエストインターフェースのクラス名を変更すると、コード生成後もエラーが出ることがあります。
その場合は、生成済みのd.dartを削除して再生成すると解決できます。
```
rm lib/model/user/user.g.dart
dart run build_runner build
```

## おわりに
今回は、FlutterでDioとRetrofitを使ってAPIと通信する方法と、型を定義する重要性を学びました。型があるとレスポンスを扱いやすくなり、開発効率が上がります。

### もう少し考えてみる
レスポンスを受け取るモデルクラスのフィールドが増えると、コードが長くなって読みにくくなることがあります。その場合は、[json_to_dart](https://javiercbk.github.io/json_to_dart/)などのツールでモデルを生成すると便利です。
