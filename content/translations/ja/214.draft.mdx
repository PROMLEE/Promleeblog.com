## デッドロックとは？
デッドロックとは、2つ以上のプロセスがリソースを保持したまま、相手の持つリソースを待ち続け、どちらも先に進めなくなる状態です。
例えば、P1がプリンターを、P2がスキャナーを保持し、それぞれが相手の装置を要求して待つと、両方とも止まってしまいます。
<Img src="/250420-013652.webp" width={300} alt="（お互いに）いつ終わるんだろう……？"/>

P1はプリンターを保持し、P2はスキャナーを保持しています。P1はP2のスキャナーを、P2はP1のプリンターを待ちます。このように互いの進行を妨げる状態がデッドロックです。
## デッドロックの発生条件 - Coffman条件
デッドロックは、次の4条件がすべて満たされたときに発生します。
1. **相互排他（Mutual Exclusion）**。リソースを同時に使えるのは1つのプロセスだけです。
2. **保持と待機（Hold and Wait）**。リソースを保持したまま、別のリソースを待ちます。
3. **非横取り（No Preemption）**。保持されているリソースを強制的に取り上げられません。
4. **循環待ち（Circular Wait）**。複数のプロセスが互いのリソースを要求し、待ち関係が輪になります。

1つでも成立しなければデッドロックは発生しません。そのため、少なくとも1つの条件を崩すことが解決の手がかりになります。
## デッドロックへの対処方法
### 予防（Prevention）
Coffman条件のうち1つが*最初から成立しないように設計する*方法です。
- 保持と待機を防ぐには、要求するリソースを一度にすべて割り当てます。すべてを確保できなければ、何も割り当てません。
- 循環待ちを防ぐには、リソースに固有の番号を付け、常に番号順に要求させます。
### 回避（Avoidance）
プロセスから要求が来たら、それを許可してもシステムが安全状態にとどまるか確認してから許可します。代表例は*銀行家のアルゴリズム（Banker's Algorithm）*です。
銀行が融資の申請を受けたとき、全体の資金が不足するおそれを計算して、承認するか判断するのに似ています。
### 検出（Detection）
デッドロックの発生を許しつつ、システムを定期的に調べて検出します。
*リソース割り当てグラフ（Resource Allocation Graph）*や*待ちグラフ（Wait-for Graph）*を使います。
検出アルゴリズムはシステムに負荷をかけることがあるため、利用には注意が必要です。
### 回復（Recovery）
デッドロックを検出してから、システムを正常な状態に戻します。主な方法は次のとおりです。
- プロセスの終了。デッドロックに陥ったプロセスを強制終了します。
- リソースの横取り。一部のプロセスからリソースを強制回収し、ほかのプロセスに割り当てます。

## マルチスレッドアプリケーションのデッドロック
スレッドを使う場合にもデッドロックはよく起きます。例えばJavaで、2つのスレッドが別々のオブジェクトのロックを取り、互いに相手のオブジェクトを待つと、デッドロックになることがあります。
```java title="Java"
// Thread 1
synchronized(objA) {
  synchronized(objB) {
    // 작업
  }
}
// Thread 2
synchronized(objB) {
  synchronized(objA) {
    // 작업
  }
}
```
対策として、ロックを取る順序を固定したり、タイムアウトを設定したりします。
