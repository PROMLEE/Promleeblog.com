## はじめに

チームにCodexとClaude Codeを導入すると、最初はうまく動いているように見えます。
時間がたつにつれて、`AGENTS.md`、`CLAUDE.md`、`README.md` に同じルールがコピーされ、どのエージェントがどのファイルを読むのか確信が持てなくなると、問題が始まります。
<Bbox>「Claude、どうか読んでほしいファイルを読んでくれ」と祈るような使い方になっていないか、振り返ってみましょう。</Bbox>
小さな変更でも相反する指示を読み込み、エージェントは不必要に長いコンテキストを抱えて作業することになります。

<br/>

良い指示ファイルは、*作業の詳細をすべて書く文書ではなく、必要なルールにすぐたどり着ける案内図*です。
この記事では、二つのファイルの役割を分け、チームが維持できる最小限の構成を作ります。

## ファイルの役割

> 指示ファイルは、数を増やすより、いつ読み込まれるかを明確にすると役立ちます。

### AGENTS.md

`AGENTS.md` には、Codex、Claude Code、Cursorなど、複数のエージェントが共通して従う*リポジトリのルール*を置きます。
ビルドとテストのコマンド、変更禁止の範囲、API互換性の原則など、ツールが変わっても同じ内容に適しています。

<br/>

Codexはプロジェクトのルートから現在の作業ディレクトリまでの `AGENTS.md` を集め、指示の既定のサイズ上限内でコンテキストに取り込みます。
[OpenAI Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)

### CLAUDE.md

`CLAUDE.md` には、Claude Codeで使うワークフローと設定を置きます。
例えば、Claude専用のフック、`/context` での確認方法、特定のパスでClaudeの計画モードを使うルールなどです。

<br/>

原文では、既定設定のClaude Codeは、対象パスに `CLAUDE.md` がある場合、`AGENTS.md` の代わりにそちらを読む場合があると説明しています。
二つのファイルを単に並べて置くと、共通ルールが読み込まれないことがあります。
[Claude Codeのメモリとプロジェクト指示](https://code.claude.com/docs/en/memory)

<Ybox>プロジェクトの指示を読み込む設定を変更していなければ、CLAUDE.mdがあるパスでAGENTS.mdの共通ルールが抜ける場合があります。両方を置くときは、実際の読み込み結果を確認します。</Ybox>

## 共通ルール

まず `AGENTS.md` を*ツール共通の取り決め*にします。
プロジェクトの情報をすべて書くより、エージェントに推測させてはいけない事実だけを残します。

```md title="AGENTS.md"
 # 공통 명령

- 패키지 설치와 실행은 npm을 사용합니다.
- 변경 후 npm run lint와 npm test를 실행합니다.

 # 변경 경계

- 공개 API 응답 형식은 요청에 명시된 경우에만 바꿉니다.
- 데이터베이스 스키마 변경은 migration과 함께 검토합니다.

 # 작업별 문서

- 인증 변경은 docs/auth.md를 읽습니다.
- 배포 변경은 docs/deploy.md를 읽습니다.
```

フォルダー構造の全体、すべての依存関係、過去の障害記録まで入れる必要はありません。
コードを検索して確認できる情報は、指示に書き写さず、必要なときに探せるようにします。

<Bbox>指示に入れるか迷ったら、その情報を知らないと安全に作業できないか、同じ失敗を繰り返すかを考えてください。該当しない情報は、作業ごとの文書やコードに置けます。</Bbox>

## Claude専用のルール

Claude Codeも使うなら、`CLAUDE.md` で先に共通ファイルを読み込み、その下にClaude専用のルールを追加します。
これでルールのコピーを避け、共通原則の修正箇所を一つに保てます。

```md title="CLAUDE.md"
@AGENTS.md

 # Claude Code 규칙

- src/database/ 변경은 먼저 계획 모드에서 영향 범위를 설명합니다.
- 작업 시작 시 /context로 로드된 프로젝트 지침을 확인합니다.
- 장기 작업은 docs/agent-state/에 결정과 검증 명령을 남깁니다.
```

`@AGENTS.md` を先に置くと、共通ルールを一か所で管理しつつ、Claude専用のルールを追加できます。
Claude Codeのドキュメントでも、共通ファイルを読み込み、その後にツール固有の指示を加える構成を案内しています。
[Claude CodeでAGENTS.mdを共有する方法](https://code.claude.com/docs/en/memory)

## 分ける基準

ファイルを分ける基準は、ルールの*適用範囲*です。
次のように判断すると、重複を減らせます。

| ルール | 場所 | 理由 |
| --- | --- | --- |
| ビルドとテストのコマンド | `AGENTS.md` | すべてのエージェントに必要です。 |
| API互換性とセキュリティ境界 | `AGENTS.md` | チーム共通の取り決めです。 |
| Claudeのフックと設定 | `CLAUDE.md` | Claude Codeだけに適用します。 |
| 個人トークンとローカルパス | ローカル設定ファイル | リポジトリへのコミットは避けます。 |
| 認証やデプロイの詳しい手順 | `docs/` | 該当する作業のときだけ読めば十分です。 |

<Rbox>APIキー、個人トークン、内部接続先などの機密値は、AGENTS.mdやCLAUDE.mdに書きません。リポジトリの指示は、チーム全員と自動化ツールが読む共通の取り決めとして扱います。</Rbox>

### サブディレクトリの指示

モノレポや大規模なサービスでは、ルートの一つのファイルですべてのルールを説明するのは難しくなります。
その場合は、`apps/admin/AGENTS.md` のように対象に近い場所に指示を置き、その領域だけで必要なルールを加えます。

*ルートのファイルには共通ルールを、下位のファイルにはその領域のルールを置きます。*
同じ内容を二つのファイルで繰り返さなければ、指示の衝突とコンテキストの浪費を防げます。

## 確認方法

指示ファイルを作成したら、実際に読み込まれるか確認します。

```text title="instruction-checklist.txt"
1. 새 세션에서 현재 작업 경로를 확인합니다.
2. 에이전트에게 적용 중인 프로젝트 지침을 요약하게 합니다.
3. 빌드 명령과 변경 금지 규칙을 질문합니다.
4. 하위 디렉터리 작업에서 추가 지침이 필요한지 확인합니다.
5. 실제 변경 후 lint와 test 결과를 기록합니다.
```

Codexでは `/status` で、現在のセッションの環境とコンテキストの状態を確認できます。
Claude Codeでは `/context` または `/memory` で、読み込まれたプロジェクトの指示を確認できます。
各ツールでファイルが実際に読み込まれることを確かめて、指示の設計を終えます。

## チームのチェックリスト

✓ 共通ルールは `AGENTS.md` の一か所で管理します。
✓ `CLAUDE.md` にはClaude専用のルールを置きます。
✓ 長い説明は `docs/` に分け、どの条件で参照するかを記載します。
✓ 個人の機密値やローカルパスは、リポジトリの指示に含めません。
✓ 新しいセッションで、実際に読み込まれた指示と検証コマンドを確認します。

## まとめ

`AGENTS.md` と `CLAUDE.md` は、必要なルールを必要な場所から読めるようにするためのファイルです。
共通ルールを一か所で管理し、ツール固有の指示は `CLAUDE.md` などの適用先に追加します。
この構成なら、ツールを変更したりチームの人数が増えたりしても、指示の重複と衝突を減らせます。
