## 状況ごとのおすすめ
### 1. ブログやドキュメントなどの静的ページ
- *Server Componentsと基本のfetch*を使う
- 必要に応じて`revalidate`で更新間隔を設定する

```ts
fetch('https://api.example.com/docs', {
  next: { revalidate: 3600 }, // 1시간마다 갱신
});
```
### 2. ログインユーザー専用のダッシュボード
- *cookies()で認証トークンを取り出してfetch*、または
- *Route HandlerのAPIとタグによる無効化*

```ts
const cookieStore = cookies();
const token = cookieStore.get('auth');
await fetch('https://api.example.com/user', {
  headers: { Authorization: `Bearer ${token?.value}` },
});
```
### 3. ボタン操作などでデータが変わる場合
- Client Componentsで*SWRを使う*のがおすすめ

```ts
'use client';
const { data, mutate } = useSWR('/api/posts', fetcher);
// 사용자 액션 후 mutate()
```
### 4. リアルタイム、または頻繁に変わるデータ
- `cache: 'no-store'`を使う
- またはクライアントから定期取得する（SWR、polling）

```ts
await fetch('https://api.example.com/status', { cache: 'no-store' });
```

## Next.jsの方向性と考え方
Next.jsは基本的に*サーバー優先*のレンダリングを目指します。
React 18で導入された*Server Components*とともに、クライアントを最小限にし、可能な限りサーバーで取得することを推奨しています。
次の利点があります。
- クライアントのJavaScriptバンドルを小さくする
- 初回表示を速める
- SEOの最適化
- コードの分離と安全性の改善
一方、クライアントが必要な場合もあるため、*バランスの取れた選択*が重要です。
## まとめ
5回にわたり、Next.jsのデータ取得を基礎から応用まで紹介しました。
単純な`fetch`から、キャッシュ、SWR、Route Handler、キャッシュの無効化まで、実際の開発で必要なほぼすべての例を扱いました。
データ取得はReactと密接に関連するため、*Reactの流れ*も理解することが大切です。
App Router時代のデータフローは、より*サーバー中心*へ進化しています。
必要なときに読み返し、戦略を立ててください。
