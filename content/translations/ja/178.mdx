## データ取得の概要
App RouterはReactのServer Components（SSR）を基盤としています。
ブラウザーで使えないサーバー専用の機能を利用でき、データ取得もその一つです。
Next.jsは基本的に*サーバーでデータを取得する方法*を推奨します。
クライアントへ渡すHTMLを事前に完成させるため、読み込み速度とSEOに有利です。
### いつ、どこで取得するか
取得できる場所は次のとおりです。
- *Server Components（既定）*：大部分のデータは、ここから取得することが推奨されます。
- *Client Components*：ユーザーの操作後など、動的に取得する必要がある場合に使います。
- *Route Handler（API route）*：バックエンドAPIとして外部システムと通信します。
App Routerはフォルダー基準のルーティングなので、`app/`内のコンポーネントファイルで取得します。

## fetchの基本
Next.jsでよく使う取得関数が`fetch`です。
ブラウザー標準の`fetch`とほぼ同じですが、Next.jsでは特別な動きをします。
JSONPlaceholderから記事を取得する例です。

```tsx title="app/page.tsx"
export default async function Page() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const posts = await res.json();
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```
Server Componentsで動作し、HTMLを描画する前にデータを取得します。
クライアントで取得して読み込み表示を出す方式より、速く安定したユーザー体験を提供します。

## fetchの動作と特徴
Next.jsの`fetch`には、次の特徴があります。
- 自動キャッシュ：既定では、同じ要求の`fetch`結果をキャッシュします。
- 無効化可能：設定でキャッシュを切れます（`cache: 'no-store'`）。
- ISR対応：一定時間ごとの更新を指定できます（`next.revalidate`）。

これらの設定は次回詳しく説明します。
