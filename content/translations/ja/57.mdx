## 観点による関連の違い（Association in Different Perspectives）
**ドメインモデル**
- 関連名を表示しますが、ソフトウェアの観点ではないため、ナビゲーションの矢印は避けます。

## キーワード（Keywords）
モデル要素を分類するためにキーワードを使います。
<Img src="/posts/240617-223758.png" width={200}/>
例えば、ユースケース図で `«actor»` を使い、人の棒人間アイコンをクラスの四角形に置き換えると、コンピューターシステムやロボットをアクターとしてモデル化できます。

| キーワード | 意味 | 使用例 |
| --- | --- | --- |
|«actor» |分類子がアクターであることを示す|クラス図の分類子名の上に表示する|
|«interface» |分類子がインターフェースであることを示す|クラス図の分類子名の上に表示する|
|\{abstract\} |抽象要素であり、インスタンス化できない|クラス図の分類子名や操作名の後ろに表示する|
|\{ordered\} |オブジェクトの集合に順序がある|クラス図の関連端に表示する|

## ステレオタイプ、プロファイル、タグ（Stereotype, Profile, Tag）
**ステレオタイプ**は、既存のモデリング概念を細分化したものです。
- UMLのステレオタイプは仕様で定義され、キーワードとは別のものです。
- UMLの拡張の仕組みを提供します。

**プロファイル**は、ステレオタイプ、*タグ*、制約の集合です。

## 相互作用図とクラス図の関係（Relationship between Interaction Diagrams and Class Diagrams）
相互作用図からクラス図の定義を作れます。
- **相互作用図を描くと、クラスとメソッドの集合が見えてきます。**
- 例えば、`makePayment` のシーケンス図から始めると、クラス図の `Register` と `Sale` の定義を導けます。
  <Img src="/posts/240617-224513.png" width={500}/>
  相互作用図のメッセージは、クラス図の操作に対応します。
  相互作用図で特定されたクラスは、クラス図で宣言します。

## 相互作用図からコードを導く例（Example of Code Derivation from Interaction Diagram）
<Img src="/posts/240617-224738.png" width={400}/>
- `A` は `X` オブジェクトに `doA()` メッセージを送ります。
- `X` は `Y` オブジェクトを作成し（`create()`）、`Y` は `X` に `doB(this)` メッセージを送ります。
- `X` はもう一度 `Y` オブジェクトを作成し（`create()`）、新しく作った `Y` に `doD(y2)` メッセージを送ります。
- 最後に、`X` は `Y` に `doE()` メッセージを送ります。

```java title="예시 코드" {numberLines: true}
public class X {
    public void doA() {
        Y y1 = new Y();
        boolean flag = y1.doB(this);
        Y y2 = new Y();
        this.doD(y2);
        y2.doE();
    }
    public void doD(Y y) {
        // doD 메소드의 구현
    }
}

public class Y {
    public boolean doB(X x) {
        Y y2 = new Y();
        x.doD(y2);
        // ...
        return true; // 예시 값
    }
    public void doE() {
        // doE 메소드의 구현
    }
}

public class Main {
    public static void main(String[] args) {
        X x = new X();
        x.doA();
    }
}
```
