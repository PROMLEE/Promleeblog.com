## はじめに

文書をアップロードすると要約し、質問に答えるサービスを作りました。
最初の顧客が月額2万ウォンを支払ってくれましたが、入金額のうちいくらを使ってよいかはまだ分かりません。
APIの請求も、開発に使うCodexやClaudeのサブスクリプション料もあるからです。
<br/>
この記事では、**顧客が一人増えるごとに赤字が減る収支構造か**を計算します。
サービスも使用量も架空の例で、月額2万ウォンも説明用の価格です。
実際のサービスの売上や利用ログは扱いません。
料金表は2026年10月15日に確認し、為替レートは計算の便宜上1ドル＝1,400ウォンと仮定します。

## 支払額と売上

まず、付加価値税10%が適用される、韓国の一般課税事業者による国内取引を想定します。
一般課税事業者の税率や仕入税額控除の基本は、[韓国国税庁の付加価値税の概要](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7693&mi=2272)を参照しました。
顧客が支払った2万ウォンをすべて売上として計上すると、税金として区分する金額まで収益性の計算に含まれます。

| 項目 | 計算 | ユーザー1人あたりの月額 |
| --- | --- | --- |
| 顧客の支払額 | 説明用の価格 | 20,000ウォン |
| 税抜売上 | 20,000 ÷ 1.1 | 約18,182ウォン |
| 決済手数料 | 支払額 × 3.3%と仮定 | 660ウォン |
| 返金・割引 | 基準シナリオ | 0ウォン |

手数料率3.3%は計算上の仮定です。特定の決済会社の契約料率を示すものではありません。
**この記事では、税抜額を売上とし、手数料は変動費として一度だけ差し引きます。**
手数料が差し引かれた入金額から、さらに手数料を引かないようにします。
返金や割引があった場合は、その期間の売上を調整し、手数料が返還されるかどうかも反映します。

## 開発ツールと運用基盤

開発時に使うサブスクリプションと、顧客への回答を生成するAPIは用途が異なります。
Codexを利用できるChatGPT PlusとClaude Codeを利用できるClaude Proは、月払いでそれぞれ20ドルです。
Claude Proの年払いは200ドルの前払いなので、月払いの20ドルとは支出の時期も異なります。[OpenAIの料金案内](https://learn.chatgpt.com/docs/pricing)、[Claudeの料金表](https://claude.com/pricing)
<br/>
サーバーやDBの費用も含めます。
Supabase Proの基本料金は月額25ドルで、付帯のコンピュートクレジットでMicro構成を一つ運用すると仮定します。
Vercel Proは月額20ドルで、開発者1名、プラン内の利用枠に収まることを条件とします。[Supabaseの料金表](https://supabase.com/pricing)、[Vercelの料金表](https://vercel.com/pricing)

| 月額費用 | 公式料金に基づく仮定 | ウォン換算 |
| --- | --- | --- |
| Supabase Pro | $25 | 35,000ウォン |
| Vercel Pro | $20 | 28,000ウォン |
| CodexまたはClaudeの開発用サブスクリプション一つ | $20 | 28,000ウォン |
| 基準の合計 | $65 | 91,000ウォン |
| 開発用サブスクリプションを二つ併用 | $85 | 119,000ウォン |

これは*基本構成を想定した費用モデル*です。実際の請求額は利用状況によって変わります。
追加の開発者枠・コンピュート・通信量や、ドメイン・メール、カードの外貨決済手数料は含めていません。
控除可能な仕入税額は費用に含めておらず、控除できない税額は実際の証憑に基づいて加算します。
<br/>
顧客からのリクエストがなくても支払うサブスクリプション料は、この試算では固定費とします。
開発用APIや追加利用料は、実際の利用量に応じて増える可能性があるため、一律に固定費とするのは避けます。
複数のサービスを開発するなら、サブスクリプション料の全額をそれぞれに重複計上せず、支出総額とサービスごとの配賦額を分けて記録します。

<Bbox>
ツール一つで運用できるなら、両方を契約する必要はありません。
基準表では一つの契約費用をこのサービスに全額配賦し、二つ使う場合は別のシナリオとして比較します。
</Bbox>

## ユーザー1人あたりの限界利益

限界利益は、売上から使用量に応じて発生する変動費を差し引いた額です。
各ユーザーから得られる限界利益を合計し、固定費を賄います。
この例では月間の処理成功件数を200件、成功1件あたりの原価を43.64ウォンと仮定します。
この原価は次回、公式API単価に架空の呼び出し記録と再試行を適用して再現します。

```text
사용자당 작업 원가 = 200 × 43.64 = 8,728원
사용자당 공헌이익 = 20,000 ÷ 1.1 − 660 − 8,728
                  ≈ 8,794원
월 운영 잔액 = 유료 사용자 수 × 공헌이익 − 91,000원
손익분기 사용자 수 = 올림(91,000 ÷ 공헌이익) = 11명
```

**基準の利用パターンでは、有料ユーザー11人から表に含めた費用を賄えます。**
10人では約3,062ウォン不足し、11人では約5,732ウォンが残ります。
計算には丸める前の値を使い、表示時だけ1ウォン単位に丸めています。

<Img src="/261015-aibiz-01-breakeven.webp" width={650} height={433} alt="想定使用量における有料ユーザー数別の月間運用収支と、開発用サブスクリプションが一つの場合と二つの場合の損益分岐点の比較"/>

開発用サブスクリプションを二つ併用すると、固定費は119,000ウォンになり、損益分岐点は14人になります。
ツールを一つ追加するときは、短縮される開発・保守時間の価値が月額28,000ウォンを上回るかを別途判断します。
短縮できた時間が実際に売上につながった場合に、その分を売上に反映します。

## 使用量が変わると

平均使用量は料金表と同じくらい重要です。
同じ2万ウォンを支払う顧客でも、処理件数が10倍になると提供原価が変わります。

| ユーザーのタイプ | 月間の処理成功件数 | 処理原価 | ユーザー1人あたりの限界利益 |
| --- | --- | --- | --- |
| 少量利用 | 50件 | 2,182ウォン | 約15,340ウォン |
| 基準 | 200件 | 8,728ウォン | 約8,794ウォン |
| 大量利用 | 500件 | 21,820ウォン | 約−4,298ウォン |

*ユーザーが増えても、利用状況によっては収支が悪化します。*
500件を処理するタイプだけが増えると、一人増えるたびに赤字が拡大します。この条件では何人集めても損益分岐点に達しません。
基準の顧客90人と大量利用の顧客10人が混在すると、月間の運用収支は約657,462ウォンの黒字です。
100人全員が基準の使用量の場合の約788,382ウォンより少なくなります。
<br/>
再試行率や文書の長さが増えても原価は変わります。
APIキャッシュやモデル選択でコストを下げられる場合がありますが、品質基準を満たす割合が維持されているかも確認します。
設定方法は[プロンプトキャッシュの記事](/blog/post/446-prompt-caching-for-coding-agents)と[モデルルーティングの記事](/blog/post/432-agent-model-routing-cost-control)を参照してください。ここでは最終的な処理原価への影響で比較します。

## この試算に含める範囲

この表は運用を点検するための初期試算です。事業全体の純利益を求めるには、開発者の人件費、サポート時間、顧客獲得費も計上します。
例えば、開発やサポートに月20時間を使い、1時間あたり3万ウォンと評価すると、60万ウォンが加わります。
基準の固定費と合わせて691,000ウォンを回収するには、同じ利用パターンで79人が必要です。
<br/>
サーバーの増強やサポート担当者の採用など、一定規模で一段上がる費用もあります。
固定費を一定とし、ユーザー数だけを増やした直線グラフでは、その変化を説明できません。
使用量、品質、基盤費用が変わるたびに、計算表を作り直します。

<Ybox>
付加価値税の納付額は、売上にかかる税額や控除可能な仕入税額などをもとに計算します。
この表は、売上から付加価値税を切り分けるための試算です。税務申告書や全体のキャッシュフロー表には使えません。
</Ybox>

## まとめ

最初の支払いが入ったら、売上額に加えて、**利用者が一人増えるといくら残るか**を確認します。
自分のサービスの支払額、月額基本料金、開発ツール費の配賦額、ユーザーごとの処理件数を表に入れてみてください。
平均的なケースに加え、利用量が多い顧客が増えた場合も計算します。
次回は呼び出し記録を使って、[AIリクエスト1件の実際の原価](/blog/post/451-ai-request-total-cost)を内訳ごとに計算します。
