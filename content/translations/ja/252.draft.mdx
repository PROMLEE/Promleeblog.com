## はじめに

私たちが作るReactアプリケーションの多くは、画面を表示するだけでなく、サーバーとデータをやり取りしながら、情報を動的に表示し、ユーザーの操作に応えます。最新のニュース記事を読み込む、ユーザーの記事を保存する、商品一覧を検索するといった作業は、いずれもサーバーとの*API通信*を通じて行います。
ただし、サーバーへのリクエストとレスポンスの受信は即座には完了せず、時間のかかる*非同期（Asynchronous）*処理です。この処理をすっきり扱い、読み込み中やエラーの状態をユーザーに伝え、必要に応じてリクエストをキャンセルすることは、フロントエンド開発の重要な課題です。
今回は、代表的な通信手段であるFetch APIとAxiosを比較し、リクエストのキャンセル、注目されるGraphQL通信、データ読み込みのためのSuspenseまで、さまざまな戦略を学びます。
## 基本的なAPI通信：Fetch API

Fetch APIはブラウザに組み込まれている強力な非同期通信インターフェースで、別途ライブラリを導入せず使えます。Promiseに基づいて動作するため、非同期コードを比較的すっきり書けます。

### 基本的な使い方（GETリクエスト）

最も基本的なGETリクエストの例です。APIには https://jsonplaceholder.typicode.com のREST APIを使います。
```tsx
import React, { useState, useEffect } from 'react';

interface Post {
  userId: number;
  id: number;
  title: string;
  body: string;
}

function FetchExample() {
  const [post, setPost] = useState<Post | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    setLoading(true);
    setError(null);

    fetch('https://jsonplaceholder.typicode.com/posts/1') // API 엔드포인트
      .then(response => {
        // fetch는 네트워크 오류가 아닌 이상 (예: 404, 500) 에러를 throw하지 않음
        // 따라서 응답 상태(ok 또는 status)를 직접 확인해야 함
        if (!response.ok) {
          throw new Error(`HTTP error! status: ${response.status}`);
        }
        // 응답 본문을 JSON으로 파싱 (이 과정도 Promise 반환)
        return response.json();
      })
      .then(data => {
        setPost(data);
      })
      .catch(err => {
        console.error("Fetch error:", err);
        setError(err);
      })
      .finally(() => {
        setLoading(false);
      });
  }, []); // 마운트 시 한 번만 실행

  if (loading) return <div>로딩 중...</div>;
  if (error) return <div>오류 발생: {error.message}</div>;
  if (!post) return null;

  return (
    <div>
      <h2>{post.title}</h2>
      <p>{post.body}</p>
    </div>
  );
}
```

### POSTリクエストとオプションの設定

POSTやその他のHTTPメソッド、ヘッダー、本文（body）のデータ送信などは、fetch関数の第2引数であるオプションオブジェクトで設定します。
```tsx
fetch('/api/users', {
  method: 'POST', // HTTP 메서드
  headers: {
    'Content-Type': 'application/json', // 요청 본문 타입
    // 'Authorization': 'Bearer YOUR_TOKEN', // 인증 토큰 등
  },
  body: JSON.stringify({ name: 'Alice', age: 30 }), // JavaScript 객체를 JSON 문자열로 변환
})
.then(response => response.json())
.then(data => console.log('Success:', data))
.catch(error => console.error('Error:', error));
```

### Fetch APIの特徴と注意点

#### メリット
- ブラウザの組み込み機能なので、ライブラリのインストールが不要です。
- Promiseベースで、使い方が比較的直感的です。
- RequestやResponseオブジェクトなど、柔軟で強力な機能があります。
#### デメリットと注意点
- **HTTPエラーの処理**：4xxや5xxのHTTPステータスコードでもPromiseはrejectされず、通常の応答としてresolveされます。`response.ok` や `response.status` を自分で確認する処理が必須です。
- **レスポンスデータの変換**：本文を使うには `response.json()` や `response.text()` などを別途呼び出す必要があり、この処理もPromiseを返します。
- **リクエストのキャンセル**：基本の機能だけではキャンセルできず、後述するAbortControllerを使う必要があります。
- **ブラウザ互換性**：古いブラウザ、特にIEでは対応していないか、ポリフィルが必要な場合があります。近年はほとんど問題になりません。
- **タイムアウト設定**：標準ではリクエストのタイムアウトを設定する機能がありません。

## Axios

Axiosは、ブラウザとNode.jsの両方で使える、広く利用されているPromiseベースのHTTPクライアントライブラリです。Fetch APIの不便な点をいくつか改善し、便利な機能を追加しています。

### 基本的な使い方

まずAxiosをインストールします。
```bash
npm install axios
  # 또는
yarn add axios
```

GETリクエストの例です。
```tsx
import React, { useState, useEffect } from 'react';
import axios from 'axios'; // axios 임포트

interface Post {
  userId: number;
  id: number;
  title: string;
  body: string;
}

function AxiosExample() {
  const [post, setPost] = useState<Post | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    setLoading(true);
    setError(null);

    axios.get<Post>('https://jsonplaceholder.typicode.com/posts/1') // GET 요청 및 응답 타입 지정
      .then(response => {
        // 응답 데이터는 response.data 안에 자동으로 파싱되어 있음
        setPost(response.data);
      })
      .catch(err => {
        // Axios는 4xx, 5xx 응답 상태 코드일 경우 에러(rejected Promise)로 처리함
        console.error("Axios error:", err);
        setError(err);
      })
      .finally(() => {
        setLoading(false);
      });
  }, []);

  if (loading) return <div>로딩 중...</div>;
  // Axios 에러 객체에서 구체적인 정보 확인 가능 (err.response, err.request 등)
  if (error) return <div>오류 발생: {axios.isAxiosError(error) ? error.message : '알 수 없는 오류'}</div>;
  if (!post) return null;

  return (
    <div>
      <h2>{post.title}</h2>
      <p>{post.body}</p>
    </div>
  );
}
```

POSTリクエストの例です。
```tsx
axios.post('/api/users', { name: 'Bob', age: 25 }) // 두 번째 인자로 데이터 객체 전달
  .then(response => console.log('Success:', response.data))
  .catch(error => console.error('Error:', error.response?.data || error.message)); // 에러 응답 확인
```

### Axiosの主な特徴とメリット

- **JSONの自動変換**：リクエスト本文をJSON文字列に変換し、レスポンスも自動でJSONオブジェクトに解析します。
- **HTTPエラーの処理**：4xxや5xxの応答ではPromiseをrejectするため、`catch` ブロックでエラーを処理できます。
- **リクエスト／レスポンスインターセプター（Interceptors）**：送信前や受信後に、ログ記録、認証トークンの追加、エラー処理などの共通ロジックを差し込める強力な機能です。
- **リクエストのキャンセル**：CancelTokenや、新しいバージョンではAbortControllerを使ってキャンセルできます。
- **タイムアウト設定**：リクエストのタイムアウト時間を簡単に設定できます。
- **CSRF対策**：クロスサイトリクエストフォージェリ（CSRF）を防ぐための機能が組み込まれています。
- **ブラウザ互換性**：古いブラウザにも比較的よく対応しています。

## FetchとAxiosの選び方：いつ、どちらを使う？

どちらも優れたツールであり、選択はプロジェクトの要件や開発者の好みによって変わります。

| 特徴 | Fetch API | Axios |
| --- | --- | --- |
| **インストール** | 不要（ブラウザ組み込み） | 必要（ライブラリ） |
| **Promiseベース** | はい | はい |
| **JSON変換** | 手動（`.json()` の呼び出しが必要） | 自動 |
| **HTTPエラーの処理** | 手動（`response.ok` の確認が必要） | 自動（Promiseをreject） |
| **リクエストのキャンセル** | AbortControllerを使用 | AbortControllerまたはCancelTokenを使用 |
| **インターセプター** | なし（自前で実装） | あり（非常に便利） |
| **タイムアウト** | なし（自前で実装） | あり（設定が簡単） |
| **互換性** | 主に最新ブラウザ | 古いブラウザにも比較的対応 |
| **バンドルサイズ** | 影響なし | ライブラリ分だけ増加 |

- **Fetchを選ぶ場合**：
  - 新たなライブラリ依存を増やしたくないとき。
  - 基本的なAPI通信だけが必要なとき。
  - バンドルサイズが非常に重要なとき。
  - HTTPエラーの処理やデータ変換を自分で制御したいとき。
- **Axiosを選ぶ場合**：
  - インターセプターが必要なとき。
  - エラー処理、タイムアウト、キャンセルを簡単に扱いたいとき。
  - JSONデータを自動変換したいとき。
  - コードの簡潔さを重視するとき。
  - ブラウザ互換性が重要なとき。

## リクエストのキャンセル：AbortController

ユーザーがページを離れたり、新しい検索語を入力して以前の結果が不要になったりした場合、進行中のAPIリクエストをキャンセルすることが大切です。不要なネットワークリソースの消費や、潜在的なメモリリークを防げます。これには標準技術のAbortControllerを使えます。

### 使い方

1. `AbortController` のインスタンスを生成します。
2. その `signal` プロパティをfetchやAxiosのリクエストオプションに渡します。
3. キャンセルしたいときに `abort()` メソッドを呼び出します。

```tsx
import React, { useState, useEffect } from 'react';
import axios from 'axios'; // Axios 사용 예시

function SearchComponent() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    if (!query) { // 검색어가 없으면 요청 안 함
      setResults([]);
      return;
    }

    // 1. AbortController 생성
    const controller = new AbortController();

    const fetchData = async () => {
      setLoading(true);
      try {
        const response = await axios.get(`/api/search?q=${query}`, {
          // 2. signal 전달
          signal: controller.signal,
        });
        setResults(response.data);
      } catch (error) {
        // 요청 취소 시 Axios는 'CanceledError' 발생시킴
        if (axios.isCancel(error)) {
          console.log('Request canceled:', error.message);
        } else {
          console.error('Search error:', error);
        }
      } finally {
        setLoading(false);
      }
    };

    fetchData();

    // cleanup 함수: 컴포넌트 언마운트 또는 query 변경 시 이전 요청 취소
    return () => {
      // 3. abort() 호출하여 요청 취소
      console.log(`Canceling request for query: ${query}`);
      controller.abort();
    };
  }, [query]); // query가 변경될 때마다 effect 재실행

  return (
    <div>
      <input
        type="text"
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="검색어 입력..."
      />
      {loading && <div>검색 중...</div>}
      <ul>
        {results.map((result: any) => (
          <li key={result.id}>{result.name}</li>
        ))}
      </ul>
    </div>
  );
}
```
`useEffect` のクリーンアップ関数で `controller.abort()` を呼び、アンマウント時や依存値（ここでは `query`）の変更により新しいリクエストを送る前に、前のリクエストをキャンセルするのが一般的なパターンです。Fetch APIでも同じように `signal` オプションを渡します。キャンセルされると、Fetchは名前が「AbortError」のエラーを発生させます。

## GraphQL通信とクライアントライブラリ
ここまでのFetchやAxiosは、主に*REST API*との通信で使います。REST APIは決められたエンドポイントでリソースをやり取りしますが、必要なデータだけを効率よく取得しにくい場合があります。これがOver-fetchingやUnder-fetchingです。
*GraphQL*は、クライアントが必要なデータ構造をクエリで指定し、サーバーがその構造に合うデータだけを返すAPIクエリ言語です。ネットワーク効率を高め、柔軟なAPIを実現できます。

### GraphQLクライアント（Apollo、urqlなど）

ReactでGraphQL APIと通信する際は、通常、専用のクライアントライブラリを使います。単なるリクエスト送信にとどまらず、GraphQLに特化した便利な機能を提供します。
- **クエリ、ミューテーション、サブスクリプションの管理**：GraphQLの操作の実行と結果の処理を容易にします。
- **キャッシュ**：正規化キャッシュなどで取得データを適切に管理し、不要なリクエストを減らします。
- **ローカル状態の管理**：クライアントの状態とリモートのデータを一緒に管理する機能もあります。
- **開発ツールとの連携**：ブラウザ拡張機能などと連携し、クエリやキャッシュ状態のデバッグを支援します。

Apollo Clientやurqlは、特に*GraphQL通信そのものを円滑にする*ことや、スキーマの活用に強みがあります。

```tsx
// Apollo Client 사용 예시 (설정은 생략)
import React from 'react';
import { useQuery, gql } from '@apollo/client';

const GET_USER = gql` /* ... GraphQL 쿼리 ... */ `;
interface UserData { /* ... */ }
interface UserVars { /* ... */ }

function UserProfileApollo({ userId }: { userId: string }) {
  const { loading, error, data } = useQuery<UserData, UserVars>(GET_USER, {
    variables: { userId },
  });
  // ... 로딩, 에러, 데이터 처리 ...
}
```

### いつGraphQLクライアントを検討する？

- バックエンドAPIがGraphQLで構築されているとき。
- クライアントで複雑なデータの組み合わせやフィールド選択が多く必要なとき。
- 強力な型システムやスキーマに基づく開発の利点を得たいとき。
- 正規化キャッシュなど、GraphQLに特化したキャッシュ戦略が必要なとき。

## これからのデータ読み込み：Suspense for Data Fetching

Reactチームは、読み込み中、エラー、成功といった状態をコンポーネント内の条件付き描画（`if (loading) ...`）で扱う代わりに、Reactの機能である*Suspense*で、より宣言的かつ一貫して扱うことを目指しています。
- **Suspense for Data Fetching**
  描画時に必要なデータがまだ準備できていない場合、コンポーネントの描画を一時停止（suspend）し、最も近い上位のSuspenseコンポーネントのfallback UIを表示します。データの読み込みが終わると、Reactが描画を再開します。
- **期待される効果**
  データの読み込みとUIの描画をより明確に分け、複数の非同期処理の読み込み状態を組み合わせたり、優先度を管理したりしやすくなります。

### Suspenseの使用例（React Queryを利用）

React Queryなどのライブラリは、実験的にSuspenseモードをサポートしています。`useQuery` フックで `suspense: true` を指定すると、読み込み中にPromiseをthrowし、Suspenseが検知してfallbackを表示できるようになります。

```tsx
import React, { Suspense } from 'react'; // Suspense 임포트
import { useQuery, QueryErrorResetBoundary } from 'react-query'; // QueryErrorResetBoundary 추가 (에러 처리용)
import { ErrorBoundary } from 'react-error-boundary'; // 에러 바운더리 라이브러리 예시
import axios from 'axios';

interface User { id: string; name: string; email: string; }
const fetchUser = async (userId: string): Promise<User> => {
  const { data } = await axios.get(`/api/users/${userId}`);
  return data;
};

// 데이터를 보여주는 실제 컴포넌트
function UserProfileData({ userId }: { userId: string }) {
  const { data } = useQuery<User, Error>(
    ['user', userId],
    () => fetchUser(userId),
    {
      suspense: true, // Suspense 모드 활성화
      // useErrorBoundary: true, // ErrorBoundary와 함께 사용 시 권장
    }
  );

  // isLoading, error 상태를 직접 처리할 필요 없음
  return (
    <div>
      <h2>{data.name}</h2>
      <p>Email: {data.email}</p>
    </div>
  );
}

// 에러 발생 시 보여줄 컴포넌트
function ErrorFallback({ error, resetErrorBoundary }: any) {
  return (
    <div role="alert">
      <p>문제가 발생했습니다:</p>
      <pre>{error.message}</pre>
      <button onClick={resetErrorBoundary}>다시 시도</button>
    </div>
  );
}

// Suspense와 ErrorBoundary로 감싸서 사용
function UserProfileSuspense({ userId }: { userId: string }) {
  return (
    // ErrorBoundary로 에러 처리 (Suspense는 로딩 상태만 처리)
    <QueryErrorResetBoundary>
      {({ reset }) => (
        <ErrorBoundary FallbackComponent={ErrorFallback} onReset={reset}>
          {/* Suspense로 로딩 상태 처리 */}
          <Suspense fallback={<div>사용자 정보 로딩 중...</div>}>
            <UserProfileData userId={userId} />
          </Suspense>
        </ErrorBoundary>
      )}
    </QueryErrorResetBoundary>
  );
}
```
このように、読み込み状態の管理をコンポーネントの外側のSuspenseコンポーネントに分けられます。データを使う側では取得に成功したデータだけを扱えばよいため、コードを簡潔にできます。エラー処理には、通常、別のErrorBoundaryコンポーネントを使います。
Suspense for Data Fetchingはまだ発展中の技術ですが、今後Reactの非同期データ処理を大きく変える可能性があります。

## おわりに

今回は、Reactでサーバーとデータをやり取りするAPI通信、非同期処理の戦略、関連ツールを比較しました。
- **Fetch API**と**Axios**はREST API通信の基本的なツールで、それぞれの長所と短所を踏まえて選びます。
- **AbortController**は、不要なAPIリクエストをキャンセルする標準的な方法です。
- **GraphQL**は必要なデータだけを効率よく要求する方式で、**Apollo Client**や**urql**はGraphQL通信そのものを円滑にすることに重点を置いています。
- **Suspense for Data Fetching**は、Reactが目指す宣言的な読み込み処理の方式であり、今後の発展に注目したい技術です。

効果的なAPI通信と非同期処理は、ユーザー体験とアプリケーションの性能に直接影響します。今回のツールや手法を理解し、状況に応じて活用して、より安定して効率よく動くReactアプリケーションを作っていきましょう。
> 次回は、フロントエンドの*セキュリティと安定性*を学びます。XSSやCSRFなどの脅威とその予防策、認証と認可の扱い方を取り上げます。
