## 开始之前
这篇文章将介绍客户端与服务器如何实时交换信息。
传统 Web 采用客户端请求、服务器响应的单向模式，但聊天、实时通知和股票行情等服务，往往需要在服务器状态变化时立即通知客户端。
<br/>
为了解决这个问题，常用的技术有 *Polling（轮询）、Webhook、SSE 和 WebSocket*。
它们的设计思路和优缺点各不相同，选择适合场景的技术对于构建高效系统非常重要。
下面一起了解它们各自的工作方式。

## 1. Polling（轮询）：客户端不断询问
Polling 是最简单、最传统的方式。
> 客户端按固定间隔不断询问服务器：“有新数据吗？”
- **工作方式**
使用 `setInterval` 等函数，让客户端每隔 1 秒或 2 秒向服务器发送一次 HTTP 请求。
- **优点**
实现简单，可以轻松用于各种服务器环境。
- **缺点**
即使数据没有变化，客户端仍会持续发送请求，给服务器和网络带来不必要的负担。
此外，数据变化到下一次轮询之间存在延迟，因此它并不是真正的实时通信。
（*Long Polling* 会让服务器等待，直到有变化再响应，从而改善这一问题，但仍有根本限制。）

## 2. Webhook：服务器主动“投递邮件”
与轮询相反，**Webhook 会在服务器发生指定事件时，将数据发送到客户端预先登记的 URL**。
- **工作方式**
客户端（通常是另一台服务器）把用于接收数据的 URL（Webhook URL）登记到对方服务器。
发生特定事件时（例如 GitHub 有新提交，或支付完成），对方服务器会向该 URL 发送 HTTP POST 请求。
- **优点**
它由事件触发，不会产生无用请求，非常适合实现服务器之间的自动化集成。
- **缺点**
客户端必须拥有可公开访问的数据接收 URL，而且它通常用于服务器之间的通信，而不是用户浏览器。

## 3. SSE（Server-Sent Events）：服务器单向“广播”
顾名思义，SSE 是一种**服务器持续向客户端单向推送数据的技术**。
<br/>
这就像广播电台不断向听众播报消息。
听众只能收听，不能向电台发送自己的声音。
因此，SSE 专用于**服务器 → 客户端的单向通信**。
<br/>
- **工作方式**
客户端通过 `EventSource` 对象向服务器请求连接。
服务器保持连接，并在有新数据时将数据流式发送给客户端。
它基于常见的 HTTP 协议，因此实现相对简单。
- **优点**
相比 WebSocket，它更轻量、实现更简单；由于基于 HTTP，也更容易兼容现有基础设施。
此外，它内置自动重连功能。
- **缺点**
它只支持单向通信，因此不适合客户端需要向服务器发送数据的场景。

## 4. WebSocket：完整的双向“电话通话”
WebSocket 让客户端与服务器建立连接后，双方可以随时自由地互相发送数据。
<br/>
这就像两个人打电话。
通话接通后，任何一方都可以随时开口交流。
它适合真正的**双向实时通信**。
<br/>
- **工作方式**
最初使用 HTTP 请求连接；双方协商后，将协议升级为 WebSocket（`ws://` 或 `wss://`），建立新的连接。
连接会一直保持，直到一方主动断开。
- **优点**
延迟极低，可以实现真正的双向实时通信。
- **缺点**
它使用不同于 HTTP 的协议，因此客户端和服务器都必须支持 WebSocket，开发复杂度也相对更高。

## 常见面试问题
面试中经常会问到你是否理解这些技术的特点和差异。

### 1. 轮询有什么问题？有哪些替代技术？
回答时应同时说明问题和替代方案。
> 轮询由客户端定期发送请求，即使没有数据变化也会**产生不必要的流量**并增加服务器负担。
此外，它难以实现完全实时的通信。
为解决这些问题，出现了服务器向客户端推送数据的 **Server Push（服务器推送）** 技术。
其中，**SSE（Server-Sent Events）** 适合服务器到客户端的单向流式传输；**WebSocket** 则适用于需要双向实时通信的场景。

### 2. SSE 与 WebSocket 有什么区别？什么时候更适合选择 SSE？
这个问题考查你对两种技术关键差异和权衡的理解。
> 最大的区别是**通信方向**。
WebSocket 支持双向通信，而 SSE 只支持服务器到客户端的单向通信。
如果项目只需接收数据，例如实时股票行情更新或社交网络动态通知，那么选择 SSE 更合适，因为客户端不需要向服务器发送数据。
SSE 基于常见的 HTTP 协议，实现更简单、也更轻量，服务器负担通常低于 WebSocket。

## 总结
今天我们介绍了四种常见的实时通信技术。
- **Polling（轮询）**
客户端持续询问，最简单但效率较低。
- **Webhook**
专用于服务器之间基于事件的通知。
- **SSE**
针对服务器到客户端的单向数据流进行优化。
- **WebSocket**
适用于需要完整双向实时通信的场景。
