## 开始之前

此前我们测试的是点击按钮后数字立即变化的*同步（Synchronous）*代码。
真实网站的操作往往没这么快。
<br/>
想象一下在外卖应用中点餐的过程。
按下下单按钮，食物并不会马上出现在眼前。
1. “正在接单……”（加载）
2. 骑手配送（等待）
3. “已送达！”（成功）或“订单取消”（错误）
<br/>
在 Web 开发中，向服务器请求数据也需要等待。
今天通过 *RTL* 提供的 `findBy`，学习如何在测试代码中处理这类*异步（Asynchronous）*操作。

## 场景：查询用户列表

先定义新需求。

> **需求**
> 1. 组件渲染时，从服务器获取用户列表。
> 2. 获取数据期间，显示“불러오는 중...”（正在加载）。
> 3. 成功获取数据后，在界面上显示用户名，例如 Leanne Graham。

这个过程会随时间推进。
测试代码也需要跟上各个阶段的变化。

## 第 1 步：编写测试（Red）

创建 `src/components/UserList.test.tsx` 文件。
本次测试的重点是创建**模拟 API**（Mock），并使用**会等待的查询**（findBy）。
<br/>
（本篇使用简单的 `global.fetch` 模拟。第 9 篇将介绍专门的 MSW 工具。）

```tsx title="src/components/UserList.test.tsx" showLineNumbers highlight="{8-18}"
import { render, screen } from '@testing-library/react';
import { vi, describe, test, expect, beforeEach, afterEach } from 'vitest';
// 아직 UserList 컴포넌트가 없으므로 import 에러가 날 수 있습니다.
import UserList from './UserList';

describe('UserList 컴포넌트 비동기 테스트', () => {
  
  // [설정] 테스트 전에 가짜 fetch 함수를 만듭니다.
  beforeEach(() => {
    // global.fetch를 스파이(Spy)로 심어서 가로챕니다.
    // 실제 서버 대신 우리가 정의한 가짜 데이터(JSON)를 반환하도록 합니다.
    global.fetch = vi.fn().mockResolvedValue({
      json: async () => [
        { id: 1, name: 'Leanne Graham' },
        { id: 2, name: 'Ervin Howell' },
      ],
    });
  });

  // [정리] 테스트가 끝나면 가짜 함수를 초기화합니다.
  afterEach(() => {
    vi.restoreAllMocks();
  });

  test('데이터를 불러오는 동안 로딩 문구가 뜨고, 이후 데이터가 표시된다', async () => {
    render(<UserList />);

    console.log('[Step 1] 렌더링 직후 확인');
    screen.debug();

    // 1. 로딩 상태 확인 (동기)
    // 렌더링 되자마자 바로 보여야 하므로 getBy를 씁니다.
    expect(screen.getByText('불러오는 중...')).toBeInTheDocument();

    console.log('[Step 2] 데이터 수신 대기');
    
    // 2. 데이터 표시 확인 (비동기)
    // 데이터는 나중에 뜨므로 getBy를 쓰면 에러가 납니다.
    // findBy는 요소가 나타날 때까지(기본 1초) 기다려줍니다.
    const userItem = await screen.findByText('Leanne Graham');
    
    console.log('[Step 3] 데이터 수신 완료 후 디버깅');
    screen.debug();

    expect(userItem).toBeInTheDocument();
  });
});
```

### getBy 与 findBy

这是异步测试中最重要的区别。

- **getByText**
  找不到元素时立即报错。
- **findByText**
  最多等待 1000 毫秒，仍找不到时才报错。
- **await**
  `findBy` 会等待结果，因此必须在前面加上 `await`。

## 第 3 步：实现功能（Green）

创建 `src/components/UserList.tsx` 并实现功能。
使用 `useEffect` 和 `fetch` 编写实际获取数据的逻辑。

```tsx title="src/components/UserList.tsx" showLineNumbers
import { useEffect, useState } from 'react';

// 사용자 데이터 타입 정의
interface User {
  id: number;
  name: string;
}

export default function UserList() {
  const [users, setUsers] = useState<User[]>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // 실제 API 호출 (테스트에서는 가짜 함수가 실행됨)
    fetch('https://jsonplaceholder.typicode.com/users')
      .then((response) => response.json())
      .then((data) => {
        setUsers(data);
        setLoading(false); // 로딩 끝
      })
      .catch((error) => {
        console.error('Error fetching data:', error);
        setLoading(false);
      });
  }, []);

  if (loading) {
    return <p>불러오는 중...</p>;
  }

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

今天练习了前端测试中比较棘手的异步逻辑。
- **findBy 查询**
  测试在异步操作之后才出现的元素时，需要使用 `await findBy...`。
- **模拟（Mocking）**
  用模拟实现替换 `global.fetch`，不必发出真实的网络请求，测试也更快、更稳定。
- **检测状态变化**
  通过测试验证了 UI 从加载到完成的整个变化过程。
<br/>
随着 API 数量增加，直接拦截 `global.fetch` 会变得难以管理。
