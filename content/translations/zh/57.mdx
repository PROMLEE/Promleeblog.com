## 设计类图（Design Class Diagram）
同一种UML类图，可以用于不同视角。
- 概念视角：**领域模型（Domain Model）**。
	<Img src="/posts/240617-223137.png" width={300}/>
- 设计视角：**设计类图（Design Class Diagram）**。
	<Img src="/posts/240617-223143.png" width={300}/>

## 不同视角中的关联（Association in Different Perspectives）
**领域模型**：
- 可以标注关联名称，但领域模型不是软件视角，所以应避免使用导航箭头。
	<Img src="/posts/240617-223346.png" width={300}/>
	- 绘制领域模型时，经常省略关联名称，虽然标注名称也是合法的。
	- 从软件视角使用类图时，在DCD中包含关联名称。

**DCD**：
- 遵循UML规范。
	<Img src="/posts/240617-223355.png" width={300}/>

## 关键字（Keywords）
通过关键字对模型元素分类。
<Img src="/posts/240617-223758.png" width={200}/>
例如，在用例图中使用`«actor»`：可以用类框代替小人形状的参与者图标，表示计算机系统或机器人参与者。

| Keyword | 含义 | 使用示例 |
| --- | --- | --- |
|«actor» |表示分类器是参与者|显示在类图的分类器名称上方|
|«interface» |表示分类器是接口|显示在类图的分类器名称上方|
|\{abstract\} |抽象元素，不能实例化|显示在类图的分类器名称或操作名称之后|
|\{ordered\} |对象集合具有固定顺序|显示在类图的关联端|

## 构造型、配置文件与标记（Stereotype, Profile, Tag）
**构造型**：表示对已有建模概念的进一步细分。
- UML构造型由UML规范定义，并不是关键字。
- 提供UML扩展机制。

**配置文件**：构造型、*标记*和约束的集合。

## 交互图与类图的关系（Relationship between Interaction Diagrams and Class Diagrams）
可以从交互图推导出类图定义。
- **画出交互图，就会得到一组类和方法。**
- 例如，从`makePayment`顺序图出发，可以在类图中推导出`Register`和`Sale`的类定义。
	<Img src="/posts/240617-224513.png" width={500}/>
	消息交互图中的消息，对应类图中的操作。
	交互图中识别出的类，也会在类图中声明。

## 从交互图推导代码的示例（Example of Code Derivation from Interaction Diagram）
<Img src="/posts/240617-224738.png" width={400}/>
- `A`向`X`对象发送`doA()`消息。
- `X`创建`Y`对象，即`create()`，然后`Y`向`X`发送`doB(this)`消息。
- `X`再次创建`Y`，即`create()`，并向新创建的`Y`发送`doD(y2)`消息。
- 最后，`X`向`Y`发送`doE()`消息。

```java title="예시 코드" {numberLines: true}
public class X {
    public void doA() {
        Y y1 = new Y();
        boolean flag = y1.doB(this);
        Y y2 = new Y();
        this.doD(y2);
        y2.doE();
    }
    public void doD(Y y) {
        // doD 메소드의 구현
    }
}

public class Y {
    public boolean doB(X x) {
        Y y2 = new Y();
        x.doD(y2);
        // ...
        return true; // 예시 값
    }
    public void doE() {
        // doE 메소드의 구현
    }
}

public class Main {
    public static void main(String[] args) {
        X x = new X();
        x.doA();
    }
}
```
