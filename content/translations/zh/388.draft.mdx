## 开始之前

上一篇创建了 *Counter* 组件，并让测试通过。
这次将重构这个组件，改善它的结构。

## 故障排查与技巧

### 1. 解决 describe 和 it 的红色下划线
即使使用 *Vitest*，编辑器（如 VS Code、WebStorm）有时也会按照 *Jest* 的语法检查代码。
这时可能找不到 `describe` 或 `it` 等函数，并出现红色下划线。
可以将 *Jest* 的类型定义包安装为开发依赖来解决。
```bash title="Terminal"
npm i --save-dev @types/jest
```
安装后，红色下划线应该就会消失。

### 2. 查看详细日志（screen.debug）

如果想看到比终端中的 **PASS** 更详细的信息，可以试试 *RTL* 提供的调试工具。
在测试代码中插入 `screen.debug()`，就会将当时的 HTML 结构输出到控制台。

```tsx title="src/components/Counter.test.tsx" showLineNumbers highlight="{10,17}"
// ... import 생략

describe('Counter 컴포넌트 동작 테스트', () => {
  test('...', async () => {
    const user = userEvent.setup();
    render(<Counter />);

    // [팁] 클릭하기 전 화면 상태 출력
    console.log('--- 클릭 전 ---');
    screen.debug(); 

    const incrementBtn = screen.getByRole('button', { name: '+' });
    await user.click(incrementBtn);

    // [팁] 클릭한 후 화면 상태 출력
    console.log('--- 클릭 후 ---');
    screen.debug(); 

    expect(screen.getByText('현재 숫자: 1')).toBeInTheDocument();
  });
});
```

这样，终端就会以文本形式显示当前渲染出来的 HTML（DOM）。
不知道测试为什么失败时，这是一种直接的排查方法。

## 重构：拆分组件

现在回到正题。
目前的 *Counter* 组件运行正常，但结构还有改进空间。
`button` 标签直接写在 *Counter* 内部，因此无法在其他地方复用这个按钮。
<br/>
接下来将按钮拆成独立的组件（`CountButton`）。
关键是，**即使改动了代码结构，验证原有功能的测试也必须继续通过**。

### 1. 创建 CountButton 组件

先创建负责显示按钮的子组件。
让它从父组件接收 `onClick` 函数和 `label`（按钮名称）。

```tsx title="src/components/CountButton.tsx" showLineNumbers
// Props 타입을 정의하여 TypeScript의 장점을 살립니다.
interface Props {
  label: string;
  onClick: () => void;
}

export default function CountButton({ label, onClick }: Props) {
  return (
    <button type="button" onClick={onClick}>
      {label}
    </button>
  );
}
```

### 2. 修改 Counter 组件

现在删除 *Counter* 组件中原有的 `button` 标签，换成刚创建的 *CountButton*。

```tsx title="src/components/Counter.tsx" showLineNumbers highlight="{2,15-16}"
import { useState } from 'react';
import CountButton from './CountButton'; // [추가]

export default function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(prev => prev + 1);
  };

  return (
    <div>
      <p>현재 숫자: {count}</p>
      
      {/* [변경] 기존 button 태그 대신 컴포넌트 사용 */}
      <CountButton label="+" onClick={handleClick} />
    </div>
  );
}
```

## 测试的价值：确认重构没有破坏功能

我们刚才改动了不少代码。
拆分了文件、增加了导入，还传递了 props。
万一漏了什么怎么办？
<br/>
这正是 TDD 发挥作用的时候。
我们**一行测试代码都没有修改**。
直接在终端运行原来的测试。

```bash title="Terminal"
npm test
```

### 查看结果
<Img src="/251221-015216.webp" width={500} alt="查看测试结果"/>
```text
 PASS  src/components/Counter.test.tsx
```
如果仍然看到绿色的 **PASS**，这次重构就成功了。
<br/>
- **原有测试**：`getByRole('button', { name: '+' })`
- **修改前**：`<button>+</button>`（可以找到）
- **修改后**：`<CountButton label="+" ... />` → 最终渲染的 HTML 仍是 `<button>+</button>`（可以找到）
<br/>
从用户和测试代码的角度来看，组件内部如何拆分并不重要。关键是*界面上有 + 按钮，点击后数字会增加*。
这就是*避免测试实现细节*的好处。
