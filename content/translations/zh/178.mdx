## 数据获取概述
Next.js的App Router基于React服务器组件（SSR）工作。服务器组件能够使用浏览器中不可用的服务器专用能力，数据获取就是其中之一。
Next.js通常推荐*在服务器端获取数据*。这样，发送给客户端的HTML在到达前已经完成，有利于页面加载速度和SEO。
### 何时、在哪里获取数据
Next.js中可以在以下位置获取数据：
- *服务器组件（默认）*：多数数据推荐在这里获取。
- *客户端组件*：用于用户交互后需要动态获取数据的场景。
- *路由处理器（API route）*：作为后端API，与外部系统通信。
App Router基于文件夹定义路由，因此数据获取代码位于`app/`目录中的组件文件内。

## fetch基础
在Next.js中，最常用的数据获取函数是`fetch`。它与浏览器原生`fetch`基本相同，但在Next.js中具有特殊行为。
例如，从JSONPlaceholder API获取文章数据的代码如下。
```tsx title="app/page.tsx"
export default async function Page() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const posts = await res.json();
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```
这段代码运行在服务器组件中，在渲染HTML之前获取数据。与客户端获取数据、显示加载状态相比，这种方式可以提供更快速、稳定的体验。

## fetch的行为与特点
Next.js的`fetch`具有以下特点：
- 自动缓存：默认对相同的`fetch`请求执行缓存。
- 可使缓存失效：可以通过配置关闭缓存，例如`cache: 'no-store'`。
- 支持ISR：可以配置定期更新数据，例如`next.revalidate`。
