## 开始之前

第 5 篇中，我们通过重构拆分了组件。
到目前为止，测试还只是在确认“界面上有没有按钮”之类的基本行为。
<br/>
但实际应用的交互要丰富得多。
点击按钮后，可能会出现一条新消息，满足特定条件时也可能弹出警告。
今天学习如何测试 *React* 的**条件渲染（Conditional Rendering）**，以及如何验证**某个元素不存在**。

## 场景：显示警告消息

为 *Counter* 组件添加一条新规则。

> **需求**：数字达到 3 或更大时，在界面上显示红色警告“숫자가 너무 커요!”（数字太大了！）。

这项功能要求界面*结构（UI）*随*状态（State）*变化。
接下来一边观察这一过程，一边编写测试。

## 第 1 步：添加测试
将 `src/components/Counter.test.tsx` 文件的全部内容替换为下面的代码。
新版本保留了原有测试，并添加了一个测试用例。
这次用 `console.log` 和 `screen.debug()` 观察测试的执行过程。

```tsx title="src/components/Counter.test.tsx" showLineNumbers highlight="{23-50}"
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Counter from './Counter';

describe('Counter 컴포넌트 동작 테스트', () => {
  
  // [기존 테스트]
  test('초기값은 0이며, + 버튼을 누르면 숫자가 1 증가한다', async () => {
    const user = userEvent.setup();
    render(<Counter />);

    const initialText = screen.getByText('현재 숫자: 0');
    const incrementBtn = screen.getByRole('button', { name: '+' });

    expect(initialText).toBeInTheDocument();
    expect(incrementBtn).toBeInTheDocument();

    await user.click(incrementBtn);

    expect(screen.getByText('현재 숫자: 1')).toBeInTheDocument();
  });

  // [신규 테스트] 조건부 렌더링 검증
  test('숫자가 3 이상이 되면 경고 문구가 나타난다', async () => {
    const user = userEvent.setup();
    render(<Counter />);

    const incrementBtn = screen.getByRole('button', { name: '+' });

    console.log('[Step 1] 초기 상태 확인');
    // 아직은 경고 문구가 없어야 합니다.
    // getByText는 찾는 요소가 없으면 에러를 내므로, 없을 때를 확인할 때는 queryByText를 씁니다.
    const warningMsg = screen.queryByText('숫자가 너무 커요!');
    expect(warningMsg).not.toBeInTheDocument();

    console.log('[Step 2] 버튼 3번 클릭 시작');
    
    // 버튼을 3번 클릭합니다.
    for (let i = 1; i <= 3; i++) {
      await user.click(incrementBtn);
      console.log(`  -> 클릭 ${i}회 완료`);
    }

    console.log('[Step 3] 클릭 후 화면 상태 디버깅');
    // 이 시점의 HTML 구조를 터미널에 출력합니다. 경고 문구가 있는지 눈으로 확인해보세요.
    screen.debug(); 

    // 이제 경고 문구가 보여야 합니다.
    expect(screen.getByText('숫자가 너무 커요!')).toBeInTheDocument();
  });
});
```

### getBy 与 queryBy

这里有两个重要概念。

- **getBy...**（例如 `getByText`）
  找到元素就返回它，**找不到就立即报错，导致测试失败**。
  确信某个元素一定存在时，可以用它。
- **queryBy...**（例如 `queryByText`）
  找到元素就返回它，**找不到就返回 null**。
  元素可能存在也可能不存在，或者本来就不应存在时，可以用它。

初始状态下**不应该出现**警告文字，因此我们使用找不到元素也不会报错的 `queryByText`，再通过 `not.toBeInTheDocument()` 验证。

## 第 3 步：实现功能（Green）

接下来修改代码，让警告文字按条件显示。
将 `src/components/Counter.tsx` 文件的完整代码改成下面这样。

```tsx title="src/components/Counter.tsx" showLineNumbers highlight="{16-21}"
import { useState } from 'react';
import CountButton from './CountButton';

export default function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(prev => prev + 1);
  };

  return (
    <div>
      <p>현재 숫자: {count}</p>
      <CountButton label="+" onClick={handleClick} />

      {/* [추가] 조건부 렌더링: count가 3보다 크거나 같으면 경고 메시지 표시 */}
      {count >= 3 && (
        <p style={{ color: 'red' }}>
          숫자가 너무 커요!
        </p>
      )}
    </div>
  );
}
```

今天测试了界面随*状态（State）*变化的*条件渲染（Conditional Rendering）*。
- **使用日志**
  在测试代码中加入 `console.log` 和 `screen.debug()`，就能直观地追踪执行过程，方便排查问题。
- **queryBy 的作用**
  要验证界面上**没有**某个元素时，应使用 `queryBy`，因为 `getBy` 在找不到元素时会报错。
- **验证动态 UI**
  我们确认了用户点击三次后，界面会随之更新。

组件现在能处理更多交互了。
不过，逻辑也越来越复杂。
UI 代码和业务逻辑（状态管理）混在组件里，以后会难以维护。
