## 开始之前
在Next.js中从Supabase获取数据，主要有两种方式。
1. 创建*自建API端点*获取数据，配合[Prisma](https://www.prisma.io/)使用。
2. 使用Supabase的*REST API*。

两种方式的优缺点如下。
| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| 自建API端点 | - 可以使用ORM，更容易操作数据库。<br/> - 能够直接访问数据库，更高效地获取数据。 | - 需要自己编写API，耗时更多。<br/> - 直接访问数据库，可能存在安全风险。<br/> - 实现比较复杂。 |
| Supabase REST API | - 无需直接访问数据库。<br/> - 代码非常简洁。 | - 获取数据时可能受到限制。<br/> - 获取数据可能需要更多时间。 |

总的来说，如果希望直观、简洁地获取数据，可以使用**Supabase REST API**；
如果希望更高效地操作数据，则可以创建**自己的API端点**。
我在这个博客中混合使用了两种方式，下面介绍具体实现。

## 使用自建API端点
### 安装Prisma
``` bash
npm i -D prisma
npm i @prisma/client
```
现在可以通过npx运行Prisma。
要在Next.js中使用Prisma，需要先完成初始化配置。
``` bash
npx prisma init
```
执行init命令后，会创建prisma文件夹，并在其中生成schema.prisma文件。
同时还会生成.env文件，需要在这里配置DB_URL。
可以在自己的Supabase项目中，依次进入Settings > Configurations > Database > Connection string查看连接字符串。
<Img src="/posts/240621-203617.png" width={800}/>

请将`[YOUR-PASSWORD]{:bash}`替换为自己的项目密码。
删除后面的`:[포트번호]/postgress`部分。
``` bash title="./.env"
DATABASE_URL="postgres://postgres.[Reference ID]:[YOUR-PASSWORD]@aws-0-ap-northeast-2.pooler.supabase.com
```
DIRECT_URL是使用Prisma客户端时需要的环境变量。
另外，如果需要部署Next.js项目，还应添加相应命令，让构建过程中也能使用Prisma客户端。
``` json title="./package.json"
{
  "scripts": {
		// ...
    "postinstall": "prisma generate"
	}
}
```

### 导入数据库结构
可以使用Prisma读取数据库结构。
``` bash
npx prisma db pull
```
执行这个命令后，数据库结构会自动添加到prisma/schema.prisma文件中。
``` prisma title="./prisma/schema.prisma (예)"
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

model Tag { // 추가
  id       BigInt     @id @unique @default(autoincrement())
  name     String     @default("")
}
```
使用导入的结构生成Prisma客户端。
``` bash
npx prisma generate
```

### 导出数据库结构
修改数据库结构后，需要将它同步到数据库。
``` bash
npx prisma db push
```
再根据修改后的结构重新生成Prisma客户端。
``` bash
npx prisma generate
```

### 创建API端点
下面创建一个使用Prisma客户端获取数据的API端点。
``` javascript title="./src/app/api/tag/route.ts"
const { PrismaClient } = require("@prisma/client");
import { NextResponse, NextRequest } from "next/server";

const prisma = new PrismaClient();

export async function GET() {
  try {
    return NextResponse.json( {data: await getTags()}, { status: 200 });
  } catch (error) {
    return NextResponse.json(
      { error: error || "Tags not Found" },
      { status: 405 },
    );
  }
}

async function getTags() {
  const Tags = await prisma.tag.findMany({
    orderBy: {
      id: "asc",
    },
  });
  return Tags;
}
```
如果需要使用Prisma的数据过滤、排序和分页等功能，请参考[Prisma Docs](https://www.prisma.io/docs/orm/prisma-client/queries/filtering-and-sorting)。

### 获取数据
现在可以在Next.js页面中，通过API端点获取数据。
`${process.env.NEXT_PUBLIC_API_BASE_URL}{:javascript}`是在`.env.local`中配置的API地址。
调试时应设为`http://localhost:3000`，部署时则需要设为`https://[your-domain]`。
``` javascript title="./src/app/tag/page.ts - SSR"
export const Page = async () => {
	let tags;
  try {
    tags = await fetch(
      `${process.env.NEXT_PUBLIC_API_BASE_URL}/api/tag`,
      { next: { revalidate: 60 } },
    )
      .then((res) => res.json())
      .then((data) => data.data);
  } catch (e) {
    tags = [];
  }
	return (
		<div>
			{tags.map((tag) => (
				<div key={tag.id}>
					<h1>{tag.name}</h1>
				</div>
			))}
		</div>
	);
};
```
``` javascript title="./src/app/tag/page.ts - CSR"
"use client";
import { useState, useEffect } from "react";

export const Page = () => {
	const [tags, setTags] = useState([]);
	useEffect(() => {
		fetch(`${process.env.NEXT_PUBLIC_API_BASE_URL}/api/tag`)
			.then((res) => res.json())
			.then((data) => setTags(data.data));
	}, []);
	return (
		<div>
			{tags.map((tag) => (
				<div key={tag.id}>
					<h1>{tag.name}</h1>
				</div>
			))}
		</div>
	);
};
```

## 使用Supabase REST API
### 安装Supabase并完成基础配置
先安装便于使用Supabase REST API的库。
``` bash
npm i @supabase/supabase-js @supabase/ssr
```
为了访问Supabase，需要设置项目的环境变量。
可以在这篇[Supabase文档](https://supabase.com/docs/guides/getting-started/quickstarts/nextjs)中部的`3. Declare Supabase Environment Variables`部分找到这些信息。
<Img src="/posts/240621-231736.png" width={800}/>

``` bash title="./.env.local"
NEXT_PUBLIC_SUPABASE_URL=https://[your-project-id].supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=[your-anon-key]
```
### 创建Supabase客户端
需要分别为*SSR*和*CSR*创建工具文件，以区分各自使用的客户端。
``` typescript title="./src/utils/serverclientSSR.ts - SSR"
import { createServerClient, type CookieOptions } from "@supabase/ssr";
import { cookies } from "next/headers";

export const createClient = () => {
  const cookieStore = cookies();

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        get(name: string) {
          return cookieStore.get(name)?.value;
        },
        set(name: string, value: string, options: CookieOptions) {
          try {
            cookieStore.set({ name, value, ...options });
          } catch (error) {
          }
        },
        remove(name: string, options: CookieOptions) {
          try {
            cookieStore.set({ name, value: "", ...options });
          } catch (error) {
          }
        },
      },
    },
  );
};
```
``` typescript title="./src/utils/serverclientCSR.ts - CSR"
import { createClient } from "@supabase/supabase-js";

export const supabase = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
);
```

### 获取数据
通过Supabase REST API获取数据的方式很简单。
``` typescript title="./src/app/tag/page.ts - SSR"
import { createClient } from "@/utils/serverclientSSR";
interface Tag { // 데이터의 타입 정의
	id: number;
	name: string;
}

const getData = async () => {
  const supabase = createClient();
  const { data }: { data: Tag[] } = await supabase
    .from("Tag") // 테이블 이름
    .select(); // 모든 열의 데이터 가져오기
  return data;
};

export const Page = async () => {
	const tags = await getData();
	return (
		<div>
			{tags.map((tag) => (
				<div key={tag.id}>
					<h1>{tag.name}</h1>
				</div>
			))}
		</div>
	);
};
```
``` typescript title="./src/app/tag/page.ts - CSR"
"use client";
import { supabase } from "@/utils/serverclientCSR";
import { useEffect, useState } from "react";
interface Tag { // 데이터의 타입 정의
	id: number;
	name: string;
}

export const Page = () => {
	const [tags, setTags] = useState<Tag[]>([]);
	useEffect(() => {
		const getData = async () => {
			const { data }: { data: Tag[] } = await supabase
				.from("Tag") // 테이블 이름
				.select(); // 모든 열의 데이터 가져오기
			setTags(data);
		};
		getData();
	}, []);
	return (
		<div>
			{tags.map((tag) => (
				<div key={tag.id}>
					<h1>{tag.name}</h1>
				</div>
			))}
		</div>
	);
};
```
过滤方法的使用方式，可以参考[Supabase - Fetch data](https://supabase.com/docs/reference/javascript/select)。

## 遇到的问题与解决方法
### .env中的DATABASE_URL受操作系统环境影响，无法修改
[GitHub issue](https://github.com/prisma/prisma/discussions/12170)
#### 解决方法
修改DATABASE_URL的变量名。
``` bash title="./.env"
NEWNAME_DATABASE_URL="postgres://postgres.[Reference ID]:[YOUR-PASSWORD]@aws-0-ap-northeast-2.pooler.supabase.com"
```
``` ts title="./prisma/schema.prisma"
datasource db {
	provider = "postgresql"
	url      = env("NEWNAME_DATABASE_URL")
}
```
### 执行Prisma generate时发生错误
`Error: EPERM: operation not permitted, unlink "C:\\**\\node_modules\\.prisma\\client\\query-engine-windows.exe"`
#### 解决方法
[Stack Overflow链接](https://stackoverflow.com/questions/46020018/error-eperm-operation-not-permitted-unlink-d-sources-node-modules-fseven)
关闭VSCode后重新打开就可以了……
## 结论

### 进一步思考：哪种方式更快
我原本以为，使用**Supabase REST API**当然会更快、更高效。
而获取数据时要经过两道过程的**自建API端点**应该更慢。
我没有使用Server Action，而是在客户端以相同条件进行了比较。
结果却发现，通过**自建API端点**获取的数据，*更早*显示在用户面前。
实际绘制到屏幕上的时间差，已经能明显感觉到。
<Img src="/posts/240621-234146.png" width={800}/>

*links*测量的是通过**自建API端点**获取数据的耗时；
*Category ~*测量的是通过**Supabase REST API**获取数据的耗时。
在关闭缓存的情况下重复测试，发现通过**自建API端点**获取的数据，*平均早100ms*显示出来。
- \<**自建API端点**的详细数据\>
	<Img src="/posts/240621-234251.png" width={300}/>
- \<**Supabase REST API**的详细数据\>
	<Img src="/posts/240621-234304.png" width={300}/>
影响最大的因素是**Queuing（排队）**。
在获取数据时，优先级较高的**自建API端点**数据会更早显示。
实际观察到的是：**自建API端点**的数据全部获取完毕后，才开始获取**Supabase REST API**的数据。
即使移除**自建API端点**，**Supabase REST API**的排队时间也没有变化。
这直接影响用户体验，因此在找到解决方法之前，我可能还是会主要使用**自建API端点**。
