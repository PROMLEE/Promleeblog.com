## 开始之前
上次我们通过 UML 类图了解了软件静态的*结构*，也就是软件的基础。
但真正的软件并不是静止的图，而是会运行并执行各种功能。
今天我们来了解 *UML 时序图（Sequence Diagram）*，它像演员演绎一幕戏一样，展示系统中的对象如何随着时间推移，通过*对话（消息）*协作。

## 什么是时序图？
时序图是 UML（统一建模语言）中的一种图表。
它是一种动态建模工具，用于按照*时间顺序*展示参与某个系统或功能的对象之间的*交互*。
顾名思义，“顺序”是重点：请求从一个对象传递到另一个对象，接收方回应或请其他对象执行操作，图表沿时间轴从上到下展示这些步骤。
<Img src="/250528-102231.webp" width={300} alt="时序图"/>

如果说类图介绍了系统中的“角色”，那么时序图就是一份“剧本”，说明这些角色会交换什么“台词（消息）”，又会在特定“场景（情境）”中如何“行动（行为）”。
时序图尤其适用于以下场景。
- **实现用例**
  具体展示系统中的对象如何协作，以满足用户需求（用例）。
- **分析复杂逻辑**
  理解涉及多个相互依赖对象的任务流程和逻辑。
- **验证并沟通设计**
  在实现前模拟系统的动态行为，发现问题，并帮助开发团队建立共同理解。
- **API 设计与文档**
  直观说明与外部系统的集成、API 调用顺序和数据流。

## 时序图的核心元素
时序图使用直观的符号和记法，清晰呈现对象之间的交互。

### 参与者、对象与生命线
- **参与者（Actor）**
  表示系统之外与其交互的人、其他系统或设备。
  通常画成小人，放在图的最左侧或最右侧，作为交互的起点或终点。
  示例：`사용자`（用户）、`외부 API 서버`（外部 API 服务器）、`센서 장치`（传感器设备）。
- **对象与生命线**
  对象是图中发送和接收消息的参与者。
  可以在矩形中写作 `객체이름:클래스이름`（例如 `myOrder:Order`），也可以只写类名 `:클래스이름`，表示匿名对象（例如 `:DatabaseManager`）。
  每个对象下方都有一条长的垂直虚线，称为*生命线（Lifeline）*。
  生命线直观地表示对象在情境中存在和活动的时间。

### 消息
消息表示一个对象请求另一个对象执行操作，或向它传递信息。
消息以两个生命线之间的箭头表示，箭头和线条的样式代表不同含义。

#### 同步消息（Synchronous Message）
- **表示方式**
  带实心箭头的实线（`->`）。
- **含义**
  发送方会*等待*接收方完成任务并返回结果。
  这与一般的函数调用类似。
- **示例**
  `사용자` 向 `로그인UI` 对象发送 `login(아이디, 비밀번호)` 消息，并等待 `로그인UI` 返回结果。

#### 异步消息（Asynchronous Message）
- **表示方式**
  带空心箭头的实线（`-->`，也可以是棒状箭头）。
- **含义**
  发送方*不会等待*接收方完成任务，而是立即继续执行后续操作。
  这种方式常见于并行处理和事件驱动系统。
- **示例**
  `주문처리시스템` 向 `이메일서비스` 发送 `sendOrderConfirmationEmail(주문정보)`，不等待邮件发送完成就继续执行后续逻辑。

#### 返回消息（Reply Message）
- **表示方式**
  虚线箭头（`<--` 或 `<..`）。
- **含义**
  接收方将同步操作的结果返回给发送方，表示控制权已经回到发送方。
  为了让图表更简洁，有时会省略显式返回消息，并通过同步消息对应的激活结束来隐含表示。
- **示例**
  `데이터베이스` 针对同步消息 `사용자정보조회()`，返回 `사용자정보객체`。

#### 自调用消息（Self-Message）
- **表示方式**
  从对象的生命线发出、再返回到同一生命线的箭头。
- **含义**
  表示对象调用自己的内部方法，适合展示对象内部的复杂逻辑。
- **示例**
  `ShoppingCart` 对象调用自己的 `calculateTotalPrice()` 方法，计算购物车总价。

#### 创建消息（Create Message）
- **表示方式**
  指向对象生命线起点的虚线箭头，常与 `<<create>>` 构造型一起使用。
  对象矩形可以放在生命线中间。
- **含义**
  表示在情境执行过程中创建了新对象。
- **示例**
  `OrderController` 收到订单请求后创建新的 `Order` 对象。

#### 销毁消息（Destroy Message）
- **表示方式**
  箭头指向对象生命线末端的“X”，常与 `<<destroy>>` 构造型一起使用。
- **含义**
  表示对象在情境执行过程中被销毁，例如移除不再需要的临时对象。
<Img src="/250528-103922.webp" width={1000} alt="时序图中的消息"/>

### 激活（Activation / Execution Occurrence）
激活表示对象接收消息并执行任务的时间段，也就是对象*正在执行*的状态。
它在生命线上画成细长的矩形，矩形高度代表任务执行时间。
对象接收同步消息后，生命线上会开始一段新的激活。
只有激活结束、任务完成后，控制权才会返回发送方。
<Img src="/250528-104254.webp" width={300} alt="激活"/>

### 控制框（Control Frame / Combined Fragment）
复杂情境除了简单的消息交换，还可能涉及条件分支（if-else）、循环、异常处理或并行处理。
时序图可以使用称为*控制框*的矩形区域明确表示这些复杂流程。
框的左上角会标注操作符，用于说明控制框的类型。

#### `alt`（Alternatives，选择分支）
根据满足的条件执行多个交互块中的一个，类似 if-else if-else 语句。
框内用虚线分隔多个操作数，每个操作数都标注保护条件（`[조건문]`）。
例如，登录时可以根据 `[인증 성공]`（认证成功）或 `[인증 실패]`（认证失败）进入不同处理流程。
<Img src="/250528-105013.webp" width={400} alt="alt 控制框"/>

#### `opt`（Optional，可选）
只有指定条件为真时才执行交互块，类似 if 语句。
例如，只有满足 `[쿠폰 사용 가능]`（优惠券可用）时才执行折扣逻辑。
<Img src="/250528-105227.webp" width={400} alt="opt 控制框"/>

#### `loop`（Loop，循环）
当条件满足或达到指定次数时重复执行交互块。
可以标注循环条件，例如 `[아이템 수만큼]`（按项目数量循环）或 `[while x < 10]`。
例如，逐项执行购物车中所有商品的 `[상품 재고 확인]`（商品库存检查）。
<Img src="/250528-105327.webp" width={400} alt="loop 控制框"/>

#### `par`（Parallel，并行）
表示控制框内的多个交互块可以并行执行。
并行块之间用虚线分隔。
例如，同时向多个外部服务请求数据，并等待各自的响应。
<Img src="/250528-105434.webp" width={400} alt="par 控制框"/>

#### `ref`（Reference，引用）
用于引用表示当前图表某个部分的独立时序图。
这样可以将复杂图表模块化，提高可读性。
框内会写出被引用的时序图名称，例如 `ref [인증 처리]`（认证处理）。

#### `break`（Break，中断）
在 `loop` 或 `alt` 等控制框中，满足某个条件时停止当前框的执行并退出，类似普通编程中的 break 语句。
例如，循环中 `[오류 발생 시]`（发生错误时）就中断。

## 示例：根据用例绘制时序图
单看理论可能不容易理解，下面以在线书店“用户搜索书籍并将其加入购物车”为例绘制时序图。
### 用例情境：主要流程
1. 用户在搜索框输入书名并点击“搜索”。
2. 搜索 UI 将搜索请求传给搜索控制器。
3. 搜索控制器请求图书服务搜索书籍。
4. 图书服务在图书存储库（例如数据库）中按书名搜索。
5. 图书存储库将匹配的书籍列表返回给图书服务。
6. 图书服务将搜索结果返回给搜索控制器。
7. 搜索控制器将结果传给搜索 UI 并显示。
8. 用户点击结果中某本书的“加入购物车”按钮。
9. 搜索 UI 请求购物车控制器添加该书。
10. 购物车控制器请求购物车服务添加书籍。
11. 购物车服务将书籍加入当前用户的购物车，并返回是否成功。
12. 如果成功，购物车控制器向搜索 UI 发送成功消息。
13. 搜索 UI 向用户显示“已加入购物车”通知。

现在，将此情境中的主要交互表示为时序图。
（用图形绘制实际时序图会更容易理解。）

### 参与对象
- `사용자:Actor`（用户）
- `검색UI:SearchUI`（搜索 UI）
- `검색컨트롤러:SearchController`（搜索控制器）
- `도서서비스:BookService`（图书服务）
- `도서저장소:BookRepository`（图书存储库）
- `장바구니컨트롤러:CartController`（购物车控制器）
- `장바구니서비스:CartService`（购物车服务）

### 主要时序：伪代码风格的消息
```txt
사용자:Actor --1. searchButtonClicked(도서명)--> 검색UI:SearchUI
  검색UI:SearchUI --2. requestSearch(도서명)--> 검색컨트롤러:SearchController
    검색컨트롤러:SearchController --3. findBooks(도서명)--> 도서서비스:BookService
      도서서비스:BookService --4. queryBooksByName(도서명)--> 도서저장소:BookRepository
      도서저장소:BookRepository --5. bookList --> 도서서비스:BookService (응답)
    도서서비스:BookService --6. searchResult(bookList) --> 검색컨트롤러:SearchController (응답)
  검색컨트롤러:SearchController --7. displayResults(searchResult)--> 검색UI:SearchUI

사용자:Actor --8. addToCartButtonClicked(선택된도서ID)--> 검색UI:SearchUI
  검색UI:SearchUI --9. requestAddToCart(선택된도서ID)--> 장바구니컨트롤러:CartController
    장바구니컨트롤러:CartController --10. addItemToCart(사용자ID, 선택된도서ID)--> 장바구니서비스:CartService
    장바구니서비스:CartService --11. isSuccess --> 장바구니컨트롤러:CartController (응답: true/false)

    장바구니컨트롤러:CartController --[isSuccess == true] (opt 프레임 시작)-->
      장바구니컨트롤러:CartController --12. notifyCartUpdateSuccess()--> 검색UI:SearchUI
      검색UI:SearchUI --13. showNotification("장바구니 추가 성공")--> 사용자:Actor
    -- (opt 프레임 종료) -->
    
    장바구니컨트롤러:CartController --[isSuccess == false] (opt 프레임 시작)-->
      장바구니컨트롤러:CartController -- notifyCartUpdateFail()--> 검색UI:SearchUI
      검색UI:SearchUI -- showNotification("장바구니 추가 실패")--> 사용자:Actor
    -- (opt 프레임 종료) -->
```

## 绘制时序图时的注意事项
为了绘制有效的时序图，可以留意以下几点。
- **聚焦一个情境**
  一张图最好只描述一个主要情境，例如用例的基本流程或某条异常流程。
  一次表达太多内容反而会让图表难以理解。
- **保持适当的抽象层次**
  无需把所有细节实现逻辑都放入图中，例如变量赋值或简单计算。
  应聚焦于对象之间有意义的消息和交互流程。
- **从左向右、从上向下**
  通常把发起交互的 Actor 或对象放在左边，时间从上向下自然延伸。
- **使用清晰的消息名称**
  消息名称最好使用动词形式，明确说明对象执行的操作。
  例如：`getUserDetails()`、`validatePassword()`、`updateInventory()`。
- **图表是沟通工具**
  只有自己看得懂的图表没有意义。
  与团队一起审查并根据反馈改进，才能建立共同理解。

今天我们了解了如何使用 UML 时序图，按照时间顺序描绘系统中的对象如何通过消息交互、像对话一样协作。
我们介绍了生命线、各种消息、激活和控制框等核心元素，并通过真实用例学习了绘制方法。
