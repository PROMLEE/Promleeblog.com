## 开始之前

用户只点击了一次“请总结这份文档”。
服务器先检索文档并调用模型，发现答案缺少依据，于是又调用了一次。
用户只做了一次操作，却产生了两次计费的模型响应。
**把一次用户请求等同于一次模型调用，可能会低估成本。**
<br/>
本例采用一项虚构的文档摘要和问答服务。
调用次数、token 数量和质量结果都是示例记录，只有官方单价来自实际价格表。
价格核查日期为 2026 年 10 月 15 日，假设汇率为 1 美元兑 1,400 韩元。

## 成本按什么单位计算

用户请求是用户尝试完成的工作，模型调用是发给 API 的单次请求。
成功任务除了收到响应，还要符合服务规定的完成标准。
本例的完成标准是回答问题，并为答案的主要论点关联文档依据。
实际运营中，也应单独记录判断任务是否完成的规则及人工审核成本。

<Img src="/261015-aibiz-02-cost-flow.webp" width={650} height={433} alt="用户请求经过检索、模型调用和质量检查，未达到标准时增加一次付费重试的成本流程"/>

在这种架构中，模型 API 之外还可能涉及文档预处理、向量嵌入、检索、存储与服务器运行。
各项成本应按相应单位计算。例如，存储通常按保存量和时长计费，嵌入则按处理量计算。
把基础月费已包含的资源再加到每项任务成本里，会重复计算。
仅将超出包含用量后实际增加的费用，或另行使用的外部服务费用，列为增量成本。

## 应用官方单价

Claude Sonnet 5.5 的标准 API 价格为普通输入每百万 token 2 美元，输出每百万 token 10 美元。
5 分钟缓存写入每百万 token 2.5 美元，缓存读取为 0.1 美元。
以下采用全球、非批处理口径，无其他处理选项的折扣或附加费用。 [Claude API 价格表](https://platform.claude.com/docs/en/about-claude/pricing)

| 单次调用假设 | Token 数量 | 美元成本 |
| --- | --- | --- |
| 普通输入 | 8,000 | $0.016 |
| 输出 | 1,000 | $0.010 |
| 合计 | 不使用缓存 | $0.026 |

按假设汇率计算，单次调用成本为 36.4 韩元。
输入应涵盖实际计费的上下文，包括系统指令、文档、对话和工具定义等。
重试可能附上上一次的回答，导致 token 数量变化。本例为简化计算，假设每次调用大小相同。
*同一文档在不同模型中的 token 数量可能不同。*
更换模型进行比较时，应按该模型返回的用量字段重新计算。

## 将失败也计入成本

假设记录中有 100 项初始任务。
90 项直接达到质量标准，另有 10 项虽然收到响应，但缺乏依据。
假设这 10 项各重试一次，最终全部通过。

| 记录项 | 数量或金额 |
| --- | --- |
| 初始任务 | 100 项 |
| 初次模型调用 | 100 次 |
| 质量不达标后的重试调用 | 10 次 |
| 计费调用合计 | 110 次 |
| 最终成功任务 | 100 项 |
| 模型成本 | 110 × 36.4 = 4,004 韩元 |
| 非模型增量成本假设 | 100 × 3.6 = 360 韩元 |
| 总任务成本 | 4,364 韩元 |
| 每项成功任务的成本 | 4,364 ÷ 100 = 43.64 韩元 |

360 韩元是假设用于外部预处理、向量嵌入等额外用量的预算，并非某个服务商的检索单价。
实际应将月度新增账单与对应批次的任务对照后分摊。
把 43.64 韩元用于[第 1 篇的盈亏计算](/blog/post/450-ai-service-unit-economics)，每位用户执行 200 项任务的成本为 8,728 韩元。
<br/>
这里的失败是指*付费响应未达到质量标准*，不属于 HTTP 错误。
Claude 说明失败请求不收费，但如果请求原本可以成功，只是客户端连接断开或超时，仍可能收费。
因此，应按实际账单判断，不能一概认定所有错误都收费，也不能仅凭用户看到失败就认为免费。 [Claude API 结算说明](https://support.claude.com/en/articles/8977456-how-do-i-pay-for-my-claude-api-usage)

<Bbox>
调用日志应记录 `task_id`、`attempt`、`model`、输入与输出 token 数、缓存 token 数、供应商请求 ID、成本和质量判定。
优先记录追踪成本所需的元数据，避免记录用户文档原文，再与供应商账单核对。
</Bbox>

## 缓存和质量变化如何影响成本

同一批假设记录如果命中缓存，成本会怎样变化？
假设第一条调用将 8,000 个输入 token 中共用的 6,000 个写入缓存，其余 109 次都在 5 分钟内读取同一缓存。
每次调用剩余的 2,000 个输入 token 与 1,000 个输出 token 照常计费。

```text
첫 호출 = 6,000 × $2.5/백만 + 2,000 × $2/백만 + 1,000 × $10/백만
        = $0.029
이후 호출 = 6,000 × $0.1/백만 + 2,000 × $2/백만 + 1,000 × $10/백만
          = $0.0146
전체 비용 = ($0.029 + 109 × $0.0146) × 1,400 + 360
          = 2,628.56원
성공 작업당 비용 = 26.2856원
```

**即使计入缓存写入成本，在这些条件下，每项成功任务的成本也会下降。**
不同客户的私有文档不会因此自动共用缓存，一天的全部请求也未必集中在 5 分钟内。
这个数字是用于观察可能效果的独立情景，仍保留第 1 篇的基准成本。
配置与命中条件见[提示词缓存文章](/blog/post/446-prompt-caching-for-coding-agents)。
<br/>
如果同样花了 4,364 韩元，却只有 80 项达到标准，则每项成功任务的成本为 54.55 韩元。
如果成功数为零，**就无法计算每项成功任务的成本**。已经发生的成本仍然存在。
应继续记录总成本和失败次数。
更换模型的实验也可以接入[验证循环](/blog/post/433-agent-code-verification-loop)，一并比较质量、响应时间与人工修改时间。

## 订阅与额度

分别记录服务 API 账单与开发工具订阅费。
使用 API 密钥调用 Codex 进行开发也会产生 API 费用，应按项目、密钥和用途与面向客户的调用分开。 [OpenAI 定价说明](https://learn.chatgpt.com/docs/pricing)
<br/>
有些订阅也包含 API 额度。
Claude Max 5x 和 20x 分别标明每月提供 100 和 200 美元的 API 额度。
使用额度需要符合资格并关联账户。额度不适用于 Claude Code 的额外使用，剩余金额在周期结束时失效。 [Claude 所含 API 额度说明](https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers)
<br/>
即使有额度，也应保留按 token 计算的资源成本。
在其下单独列出已使用额度和新增现金支出，才能比较额度过期或用尽后的盈亏。
这三篇文章的基准是假设只用一项低价月订阅，API 额度为 0 美元，不计 Max 的订阅费或权益。

## 结语

成本计算应从**完成达到质量标准的工作所花费的总成本**出发。
可以先选取自己的 100 项任务，在同一期间记录初次调用、重试、最终成功数与增量成本。
再检查减少 token 后，完成率和人工修改时间能否维持。
