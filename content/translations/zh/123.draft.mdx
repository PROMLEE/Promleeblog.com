## 开始之前
> 本文基于 Flutter 3.24 编写。

开发应用或 Web 前端时，经常需要使用后端接口或开放 API。调用 API 需要进行 HTTP 通信。在 Flutter 中，可以使用 Dio 和 Retrofit 完成 API 通信。
当然，也可以使用 HTTP 包，但 Dio 和 Retrofit 能让 API 调用更加方便。尤其是 Retrofit，可以通过类型定义轻松处理 API 响应，提高开发效率。
本文介绍在 Flutter 中使用 Dio 和 Retrofit 进行 API 通信的方法，以及类型定义的重要性。

## 1. 安装依赖包
要使用 Retrofit，需要安装包括 Dio、Retrofit 在内的 4 个包。另外，还有 3 个包仅在开发时使用，因此添加到 dev_dependencies 中。
安装命令如下。
```
dart pub add json_annotation dio retrofit
dart pub add --dev build_runner retrofit_generator json_serializable
```
确认 pubspec.yaml 文件中已添加以下内容（版本以撰写时为准）。
```yaml title="pubspec.yaml"
dependencies:
	retrofit: ^4.4.2
	dio: ^5.7.0
	json_annotation: ^4.9.0

dev_dependencies:
	build_runner: ^2.4.13
	retrofit_generator: ^9.1.5
	json_serializable: ^6.9.0
```
各个包的作用如下。
- dio：用于 HTTP 通信。
- retrofit：用于 API 通信。
- json_annotation：用于 JSON 序列化与反序列化。
- build_runner：用于生成代码。
- retrofit_generator：生成使用 Retrofit 所需的代码。
- json_serializable：生成 API 请求过程中进行 JSON 序列化与反序列化所需的代码。

### 2.1 编写 API 请求的模型类
编写 API 请求所需的模型类，示例代码如下。
```dart title="lib/model/user_dto.dart"
import 'package:json_annotation/json_annotation.dart';
part 'user_dto.g.dart';

@JsonSerializable()
class UserDto {
	final int id;
	final String name;
	final String username;
	final String email;
	final Address address;
	final String phone;
	final String website;
	final Company company;

	UserDto({
		required this.id,
		required this.name,
		required this.username,
		required this.email,
		required this.address,
		required this.phone,
		required this.website,
		required this.company,
	});

	factory UserDto.fromJson(Map<String, dynamic> json) => _$UserDtoFromJson(json);
	Map<String, dynamic> toJson() => _$UserDtoToJson(this);
} 

@JsonSerializable()
class Address {
	final String street;
	final String suite;
	final String city;
	final String zipcode;
	final Geo geo;

	Address({
		required this.street,
		required this.suite,
		required this.city,
		required this.zipcode,
		required this.geo,
	});

	factory Address.fromJson(Map<String, dynamic> json) => _$AddressFromJson(json);
	Map<String, dynamic> toJson() => _$AddressToJson(this);
}

@JsonSerializable()
class Geo {
	final String lat;
	final String lng;

	Geo({
		required this.lat,
		required this.lng,
	});

	factory Geo.fromJson(Map<String, dynamic> json) => _$GeoFromJson(json);
	Map<String, dynamic> toJson() => _$GeoToJson(this);
}

@JsonSerializable()
class Company {
	final String name;
	final String catchPhrase;
	final String bs;

	Company({
		required this.name,
		required this.catchPhrase,
		required this.bs,
	});

	factory Company.fromJson(Map<String, dynamic> json) => _$CompanyFromJson(json);
	Map<String, dynamic> toJson() => _$CompanyToJson(this);
}
```

### 2.2 编写 API 请求的接口
```dart title="lib/model/user.dart"
import 'package:dio/dio.dart';
import 'package:retrofit/retrofit.dart';
import 'user_dto.dart';

part 'user.g.dart'; // 생성될 파일

@RestApi(baseUrl: "https://jsonplaceholder.typicode.com") // base url
abstract class UserApi {
	factory UserApi(Dio dio, {String baseUrl}) = _UserApi;

	@GET("/users") // 요청할 API
	Future<List<UserDto>> getUsers(); // 요청할 API의 응답을 받을 모델 클래스
}
```
## 3. 生成代码
写好上述代码后，IDE 中可能出现错误（红色下划线）。这表示需要生成代码。
在项目根目录中运行以下命令来生成代码。
```
dart run build_runner build
```
确认对应文件夹中已生成以下文件。
```
lib/model/user_dto.g.dart
lib/model/user.g.dart
```
如果错误已经消失，就可以准备调用 API 了。

  final dio = Dio();
  final client = GetUserApi(dio);

  client.getUsers().then((userList) => {

## 5. 其他配置方法
### 5.1 API 请求中传递参数
```dart
@GET('/users/{id}')
Future<UserDto> getUserByPathId(@Path() int id); // 파라미터 전달
```
### 5.2 API 请求中传递查询参数
```dart
@GET('/users')
Future<List<UserDto>> getUserByQueryId(
	@Query('id') int id,
); // 쿼리 파라미터 전달
```
### 5.3 API 请求中传递请求头
传递固定请求头时，按如下方式编写。
```dart
@GET('/users')
@Headers(<String, dynamic>{
	'Content-Type': 'application/json',
	'Authorization': 'Bearer {token}',
})
Future<List<UserDto>> getUsers(); // 헤더 전달
```
动态传递请求头时，按如下方式编写。
```dart
@GET('/users')
Future<List<UserDto>> getUsers(
	@Header('Content-Type') String content_type, 
	@Header('Authorization') String authorization,
); // 헤더 전달
```
### 5.4 API 请求中传递请求体
```dart
@POST('/users')
Future<UserDto> createUser(@Body() UserDto user); // 바디 전달
```

## 问题与解决方法
### 1. 修改类名时
修改请求接口的类名后，即使重新生成代码，也可能出现错误。
这时删除生成的 d.dart 文件，再重新生成即可解决。
```
rm lib/model/user/user.g.dart
dart run build_runner build
```

## 结语
本文介绍了在 Flutter 中使用 Dio 和 Retrofit 进行 API 通信的方法，以及类型定义的重要性。通过类型定义，可以轻松处理 API 响应，提高开发效率。

### 进一步思考
接收 API 响应的模型类字段越多，代码就越长，可读性也可能下降。此时使用 [json_to_dart](https://javiercbk.github.io/json_to_dart/) 等工具生成模型类会更方便。
