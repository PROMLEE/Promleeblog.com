## 开始之前

我做了一项服务，用户上传文档后，它可以生成摘要并回答问题。
第一位客户每月支付 2 万韩元，但我还不知道到账的钱里有多少可以支配。
因为既要付 API 账单，也要付开发时使用的 Codex 或 Claude 订阅费。
<br/>
本文计算的是**每增加一位客户，亏损是否会减少**。
示例服务和使用量都是虚构的，月费 2 万韩元也仅用于说明。
本文不披露实际服务的收入或使用日志。
价格表于 2026 年 10 月 15 日核对。为便于计算，假设 1 美元兑换 1,400 韩元。

## 支付金额与营业收入

先假设是在韩国境内进行的交易，适用一般纳税人的 10% 增值税税率。
关于一般纳税人税率和进项税额抵扣的基本说明，参阅[韩国国税厅增值税概览](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7693&mi=2272)。
如果把客户支付的 2 万韩元全部记为收入，原本应单独列出的税额也会混入盈利计算。

| 项目 | 计算 | 每位用户的月金额 |
| --- | --- | --- |
| 客户支付金额 | 示例价格 | 20,000 韩元 |
| 不含增值税的收入 | 20,000 ÷ 1.1 | 约 18,182 韩元 |
| 支付手续费 | 假设为支付金额的 3.3% | 660 韩元 |
| 退款与折扣 | 基准情景 | 0 韩元 |

3.3% 是假设费率，并非任何支付机构的实际合同费率。
**本文的收入不含增值税，手续费只在变动成本中扣一次。**
如果结算到账金额已经扣除了手续费，就别再扣一次。
发生退款或折扣时，还要调整当期收入，并核对手续费是否退回。

## 开发工具与运营基础设施

开发订阅与为客户生成答案的 API 用途不同。
包含 Codex 的 ChatGPT Plus 与包含 Claude Code 的 Claude Pro，按月付费均为 20 美元。
Claude Pro 的年度付款为预付 200 美元，因此现金支出时间与每月支付 20 美元不同。 [OpenAI 定价说明](https://learn.chatgpt.com/docs/pricing)、[Claude 价格表](https://claude.com/pricing)
<br/>
服务器与数据库也要计入。
Supabase Pro 每月基础费用为 25 美元，这里假设使用所含的计算额度运行单个 Micro 实例。
Vercel Pro 按每月 20 美元、一个开发者席位且不超过所含用量计算。 [Supabase 价格表](https://supabase.com/pricing)、[Vercel 价格表](https://vercel.com/pricing)

| 月成本 | 基于官方价格的假设 | 折合韩元 |
| --- | --- | --- |
| Supabase Pro | $25 | 35,000 韩元 |
| Vercel Pro | $20 | 28,000 韩元 |
| 一项 Codex 或 Claude 开发订阅 | $20 | 28,000 韩元 |
| 基准合计 | $65 | 91,000 韩元 |
| 同时使用两项开发订阅 | $85 | 119,000 韩元 |

这是*基础配置的成本模型*，最终账单会随实际使用情况变化。
这里不计额外席位、计算资源、流量、域名、邮件及银行卡换汇手续费。
可抵扣的进项税不计入成本。不可抵扣的税额，应根据实际凭证加上。
<br/>
即使没有客户请求也要支付的订阅费，在本例中列为固定成本。
开发用 API 或额外用量费用会随实际使用而增加，应根据情况分类。
如果在开发多个服务，要分别记录总支出和分摊给各服务的金额，避免把整笔订阅费重复计入每项服务。

<Bbox>
如果一项工具足以支撑运营，只订阅这一项即可。
基准表把一项订阅的费用全部分摊给本服务，并单独比较使用两项订阅的情景。
</Bbox>

## 每位用户的边际贡献

边际贡献是收入扣除随用量产生的变动成本后剩下的金额。
每位用户留下的边际贡献合在一起，用于覆盖固定成本。
本例假设每月成功完成 200 项任务，每项成功任务的成本为 43.64 韩元。
下一篇会用官方 API 单价、假设调用记录和重试来复现这个成本。

```text
사용자당 작업 원가 = 200 × 43.64 = 8,728원
사용자당 공헌이익 = 20,000 ÷ 1.1 − 660 − 8,728
                  ≈ 8,794원
월 운영 잔액 = 유료 사용자 수 × 공헌이익 − 91,000원
손익분기 사용자 수 = 올림(91,000 ÷ 공헌이익) = 11명
```

**按基准用量计算，从 11 位付费用户开始，就能覆盖表中计入的费用。**
10 位用户时约差 3,062 韩元，11 位时约剩 5,732 韩元。
计算使用未舍入数值，只有展示金额时才四舍五入到韩元。

<Img src="/261015-aibiz-01-breakeven.webp" width={650} height={433} alt="按假设用量比较不同付费用户数下的月度运营结余，以及使用一项或两项开发订阅的盈亏平衡点"/>

同时使用两项开发订阅时，固定成本变为 119,000 韩元，盈亏平衡点变为 14 位用户。
决定是否多用一个工具时，要单独判断节省的开发与维护时间是否值每月 28,000 韩元。
节省的时间如果尚未转化为实际收入，就不要把它直接加到收入上。

## 用量变化的影响

平均用量与价格表同样重要。
即使都支付 2 万韩元，任务数量相差十倍，提供服务的成本也会不同。

| 用户类型 | 每月成功任务 | 任务成本 | 每位用户的边际贡献 |
| --- | --- | --- | --- |
| 轻度 | 50 项 | 2,182 韩元 | 约 15,340 韩元 |
| 基准 | 200 项 | 8,728 韩元 | 约 8,794 韩元 |
| 高用量 | 500 项 | 21,820 韩元 | 约 -4,298 韩元 |

*用户增加，盈亏未必改善。*
如果增加的都是每月 500 项任务的用户，每多一位就会多亏一笔。在这个条件下，不存在能实现盈亏平衡的用户数。
90 位基准用户加上 10 位高用量用户，月度运营结余约为 657,462 韩元。
这低于 100 位用户都按基准用量计算时的约 788,382 韩元。
<br/>
重试率上升或文档变长，也会改变成本。
API 缓存与模型选择可以降低成本，同时要确认通过质量要求的比例是否保持稳定。
配置方法参见[提示词缓存文章](/blog/post/446-prompt-caching-for-coding-agents)和[模型路由文章](/blog/post/432-agent-model-routing-cost-control)。这里着重比较它们对最终任务成本的影响。

## 这份计算涵盖什么

这张表用于初步检查运营情况。要计算整个业务的净利润，还需要计入开发人员的人力成本、支持时间与获客成本。
例如，如果每月投入 20 小时用于开发和支持，按每小时 3 万韩元估值，就会增加 60 万韩元的成本。
加上基准固定成本，需要收回 691,000 韩元。在相同用量模式下，需要 79 位用户。
<br/>
还有一些成本会在达到特定规模时跳升，例如扩容服务器或聘请支持人员。
固定成本不变、只让用户数不断增长的直线图，无法描述这一段。
因此，当用量、质量或基础设施成本变化时，都要重新计算。

</Ybox>

## 结语

收到第一笔付款后，要确认的是**每多一位用户，能剩下多少钱**。
可以把自己的收款金额、每月基础费用、开发工具分摊额和各类用户的任务数填进表里。
除了平均用量，也要计算高用量用户增加的情况。
