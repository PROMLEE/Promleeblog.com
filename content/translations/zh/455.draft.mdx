## 开始之前

文档服务的使用量增加后，回答变慢了。
团队原先只看模型 API 成本，现在开始考虑是该扩容服务器，还是换用更快的模型。
但首先要区分：是检索慢、模型排队时间长，还是输出变长了？
**找到请求的瓶颈，才能判断需要增加哪些资源、会产生多少成本。**
<br/>
本文沿着一项虚构文档服务的请求流程绘制基础设施图。
这里不预设服务需要自行运营 GPU。
官方技术和能源资料于 2026 年 10 月 16 日核查，成本计算中的运营金额和吞吐量均为示例假设。

## 训练与推理

训练是利用数据调整模型权重的过程。
推理则使用已有权重计算输入对应的结果。
用户每次上传文档时，无须重新训练整个模型。
本例先检索文档，将相关内容加入输入，再用已经准备好的模型回答。
<br/>
拆分文档和计算向量嵌入等预处理，也应与训练区分。
嵌入是为检索生成表示的独立任务，可能带来存储与更新成本。
如果选择继续训练模型，除了训练本身，还要加上数据准备、评估和部署的成本。
仅凭公开的 API 价格表，无法判断模型供应商如何将所有内部成本分摊到当前 API 价格中。

## 计算与内存

GPU 可以并行执行大规模矩阵运算。
HBM 是以高带宽供给数据的内存，参与保存模型权重和处理任务状态。
多设备共同处理时，设备之间的数据传输也很重要。
NVIDIA 对 Blackwell 的介绍也将 NVLink 通信和机架冷却与 GPU 运算分开说明。 [NVIDIA Blackwell 架构](https://www.nvidia.com/en-us/data-center/technologies/blackwell-architecture/)
<br/>
因此，**仅凭峰值算力无法预测服务每秒能处理多少请求。**
还要确认内存能否容纳模型和并发任务的状态，以及搬运数据要花多久。
文档越长，输入处理量和任务状态可能越大。多个客户同时使用时，可用内存也会变化。
检索数据库或文件存储的瓶颈，也未必能靠增加模型 GPU 解决。

## 输入处理与生成

推理内部的输入处理阶段，与生成输出 token 的阶段有不同特点。
`prefill` 读取输入提示词，`decode` 则继续生成后续 token。
NVIDIA 说明，在特定注意力配置下，前者更容易受算力限制，后者更容易受 HBM 带宽限制。缓存和推理方式也可能改变瓶颈位置。 [NVIDIA 推理设计分析](https://developer.nvidia.com/blog/co-designing-ai-model-attention-for-fast-interactive-long-context-inference)
<br/>
本例可以分别记录到首个 token 的时间与完成整个回答的时间。
如果首个响应较慢，检查排队、检索和输入处理时间。如果只有生成阶段较长，检查输出长度和生成吞吐量。
除了平均值，也要查看慢请求卡在哪个阶段，才能判断实际用户体验。
*输入 token 和输出 token 的价格差异，不能仅靠一种 GPU 部件的价格解释。*

## 电力与冷却

计算设备需要稳定供电，也需要排出热量才能使用。
电网接入、变压器和冷却设施的准备周期，可能限制数据中心扩建。
IEA 在 2026 年 10 月 14 日的报告中，讨论了将数据中心接入电力系统时的政策、监管与企业策略。 [IEA Powering Artificial Intelligence](https://www.iea.org/reports/powering-artificial-intelligence)
<br/>
这些行业层面的约束，无法直接换算成单次 API 请求的耗电量。
设备类型、批处理和空闲状态以及设施运营条件都没有公开。
API 用户可以先管理账单、质量与响应时间。自行运营基础设施时，再补充电力与设施成本的分摊依据。
供应商对数据中心的投资，也不应作为我们服务直接购置的资产重复计入。

## 吞吐量与利用率

为了了解自营成本，假设一套配置每月分摊成本为 600 万韩元。
这里假设已经包含按期间分摊的设备费用、电力、设施、网络和运维时间。
它并非实际 GPU 租赁报价，也不代表任何具体数据中心的成本。

| 假设月度分摊成本相同 | 成功完成的任务数 | 每项任务的分摊成本 |
| --- | --- | --- |
| 6,000,000 韩元 | 60,000 项 | 100 韩元 |
| 6,000,000 韩元 | 120,000 项 | 50 韩元 |

**如果用相同资源保持质量并完成更多工作，每项任务的成本就可能下降。**
但设备利用率较高，不一定意味着成功完成的任务更多。
重试或不必要的长输出也会让 GPU 忙碌，却不一定增加客户完成的工作。
电力等变动成本也会随用量变化，因此上表仅用于说明总成本不变时的敏感度。
<br/>
增大批次可能提高吞吐量，也可能增加等待任务凑成一批的时间。
为了降低延迟而预留设备，则可能提高单位成本。
先设定质量标准和延迟目标，再在符合条件的范围内比较吞吐量与成本。

<Bbox>
除了月度账单，也可以记录成功任务数、重试比例、首个响应与全部完成所需的时间，以及最大并发任务数。
这些数据有助于判断是需要更贵的资源，还是现有资源使用效率不高。
</Bbox>

## 效率与行业需求

用更少资源处理一次请求，与整个行业的资源需求下降，是两个问题。
IEA 在预测数据中心需求时，除了效率变化，也考虑供应链瓶颈、投资和融资条件。 [IEA 能源与 AI 的关键问题](https://www.iea.org/reports/key-questions-on-energy-and-ai/executive-summary)
即使模型更高效，使用量、任务长度和新功能的使用增加，也可能改变总资源需求。
如果使用量增长不足以抵消效率改善，总需求也可能下降。
<br/>
供应限制对不同企业的影响也不同。
出售紧缺零部件的企业，与必须高价购买这些零部件的服务企业，利润变化未必同向。
如果不了解长期合同、交货周期、销售价格和成本结构，仅凭行业新闻很难判断企业的盈利能力。

<Ybox>
“AI 请求增加 → GPU 需求增长 → 相关企业利润增加”的每一步都有条件。
还应分别核对瓶颈缓解后的价格竞争、利用率和投资回收情况。
</Ybox>

## 结语

AI 基础设施是由**计算、内存、通信、设施与运营共同组成的处理系统**。
可以先在请求流程图上标出耗时较长的环节，以及成本按什么单位增加。
有时，先整理输入或改进验证方式，比增加设备更有必要。
下一篇将介绍基础设施与服务的增长如何体现在企业的损益和现金流中。
